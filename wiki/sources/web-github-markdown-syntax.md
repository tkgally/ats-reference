# 資料：GitHubの基本的な書式（GitHub Docs）

GitHubの公式ドキュメント「Basic writing and formatting syntax」にある、GitHub上で使えるMarkdownの書き方の要約です（2026年10月21日に確認）。

- URL：[https://docs.github.com/en/get-started/writing-on-github/getting-started-with-writing-and-formatting-on-github/basic-writing-and-formatting-syntax](https://docs.github.com/en/get-started/writing-on-github/getting-started-with-writing-and-formatting-on-github/basic-writing-and-formatting-syntax)
- 発行者：GitHub
- 確認した日：2026年10月21日
- 種類：ウェブ上の資料（エージェントが調べたもの。`raw/`の資料ではない）

## 内容の要約

- 見出し：行頭に1〜6個の`#`を置く。見出しが2つ以上あると、ファイル上部の目次（Outline）が自動で作られる。
- 文字の装飾：太字は`**`、斜体は`*`または`_`、取り消し線は`~~`で囲む。下付き・上付き・下線は`<sub>`、`<sup>`、`<ins>`のタグを使う。
- 引用：行頭に`>`。コード：1行は`` ` ``で囲み、複数行は`` ``` ``で囲む。
- リンク：`[表示名](URL)`。リポジトリ内のファイルへは`./`や`../`を使った相対パスで書ける。表示名は1行に収める（途中で改行するとリンクにならない）。
- 見出しへのリンク：`#見出しのアンカー`。アンカーは見出しを小文字にし、空白をハイフンに、その他の記号を取り除いて作られる。同じ見出しが複数あると末尾に`-1`などが付く。見出しを書き換えるとアンカーも変わる。
- 箇条書き：`-`、`*`、`+`、または`1.`。入れ子にするときは、親の項目の本文に揃えて字下げする。
- タスクリスト：`- [ ] 項目`（未完了）、`- [x] 項目`（完了）。
- メンションと参照：`@ユーザー名`で本人に通知する。`#`で課題やプルリクエストを参照する。`:絵文字コード:`で絵文字を入れる。
- 画像：`![説明](パスまたはURL)`。
- 表：この資料には書き方が載っていない（GitHub Flavored Markdownの仕様を参照するよう案内されている）。
- 改行：課題・プルリクエスト・ディスカッションでは、1回の改行がそのまま改行になる。`.md`ファイルでは、1回の改行では改行にならず、行末に半角スペース2つ、行末のバックスラッシュ、または`<br/>`を使う。どちらでも、空行を入れると段落が分かれる。
- エスケープ：記号の前にバックスラッシュを置くと、記号がそのまま表示される（課題やプルリクエストの題名では使えない）。
- 隠しコメント：`<!-- 内容 -->`は表示されず、ソースにだけ残る。
- 注意書き（アラート）：引用の先頭に`[!NOTE]`、`[!TIP]`、`[!IMPORTANT]`、`[!WARNING]`、`[!CAUTION]`のいずれかを書く。多用せず、1つの文書に1〜2個にとどめるよう勧められている。
