# 資料：gitignoreの規則の書き方（Git公式ドキュメント）

Git公式ドキュメントにある、`.gitignore`の規則（パターン）の書き方と優先順位の要約です（2026年10月19日に確認）。

## 資料の情報

- gitignore：[https://git-scm.com/docs/gitignore](https://git-scm.com/docs/gitignore)
- 発行者：Gitプロジェクト（公式ドキュメント）
- 確認した日：2026年10月19日
- 種類：ウェブ上の資料（エージェントが調べたもの。`raw/`の資料ではない）

## 内容の要約

- 空行：何にも一致しない。区切りに使える。
- コメント：行頭が`#`の行。`#`で始まる名前に一致させたいときは`\#`と書く。行の途中からのコメントは使えない。
- 行末の空白：`\`で保護しない限り無視される。
- 否定：行頭の`!`は、前の規則で除外されたファイルをもう一度対象に戻す。親のフォルダーが除外されていると、その中のファイルは戻せない（Gitは除外されたフォルダーの中を見ない）。
- 行末の`/`：フォルダーだけに一致する。`foo/`はフォルダー`foo`に一致し、ファイル`foo`には一致しない。
- 行頭または途中の`/`：`.gitignore`のあるフォルダーからの位置を指す。`/`を含まない規則は、それより下のどの深さにも一致する。
- ワイルドカード：`*`は`/`以外の任意の文字列、`?`は`/`以外の1文字、`[a-z]`は範囲内の1文字、`\`は次の文字の特別な意味を打ち消す。
- `**`：`**/foo`はどの階層の`foo`にも一致、`abc/**`は`abc`の中のすべて、`a/**/b`は間に0個以上のフォルダーがある`b`。
- 優先順位（高い順）：コマンドラインの指定、対象のフォルダーから作業ツリーの最上位までの`.gitignore`（深いフォルダーのものが優先）、`.git/info/exclude`、`core.excludesFile`で指定したファイル。同じ段階の中では、最後に一致した規則が決める。
- 例：`*.log`と`!keep.log`の組み合わせは、`keep.log`だけを残す。`/build/`は最上位の`build`フォルダーだけ、`tmp/`はどの階層の`tmp`フォルダーも対象にする。
