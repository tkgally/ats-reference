# 資料：TCU GitHub Copilot 学生向け利用手順（2026年10月14日）

大学の組織「TCU Copilot Teaching Platform」で、授業用のリポジトリを作り、GitHub Copilotデスクトップアプリから操作するまでの、履修学生向けの手順書の要約です。

## 資料の情報

- 種類：人間が`raw/`に置いた文書（`raw/`にあるdocxファイル「TCU GitHub Copilot 学生向け利用手順」）
- 日付：2026年10月14日（`raw/`に置かれた日）。作成者は文書に書かれていない。
- 個人情報：含まない。学籍番号の例は伏せ字、名字は例（tanaka）のみ。
- 性質：2026年10月13日の資料の「要確認」だった点の多くに答える内容。この資料が書かれた時点の設定であり、変わりうる。

## 内容の要約

### 組織とアカウントのしくみ

- GitHubの組織（Organization）は「TCU Copilot Teaching Platform」（組織名はtokyo-city-university）。
- 履修学生は、あらかじめ授業用のMicrosoft Entra IDグループと、GitHubのTeamのTeam Sync（同期）の対象に設定されている。授業ごとにTeamがあり、履修者が登録される。
- Copilot Business（有償版）の利用枠（Seat）は授業用Teamに割り当てられている。組織への参加、Teamへの所属、利用枠の適用は、学生が個別に設定する作業ではない。
- 学生は、教員が指定した命名規則に従って、授業用のリポジトリを各自で作る。

### 使い始めるまでの流れ

1. ブラウザでGitHubにサインインし、大学のSSO認証を行う。SSOのURLは`https://github.com/orgs/tokyo-city-university/sso`。
2. GitHub上で試しのリポジトリを作る。
3. GitHub Copilotデスクトップアプリをダウンロードする（公式ドキュメントの案内に従う）。
4. アプリからGitHubにサインインし、作ったリポジトリを開く。
5. Copilotのチャットからリポジトリを操作する。

### アカウントと認証

- GitHubアカウントを持っていない人（資料は「大部分」と見ている）は、画面の案内に従って新しく作り、そのアカウントでサインインしてから、大学のMicrosoft Entra IDアカウントでSSO認証する。つまり、授業ではふつうの個人のGitHubアカウントを使い、大学の組織にSSOでつなぐ方式である。
- GitHubのサインインと大学のSSO認証は別の処理で、組織のリポジトリやCopilotを使うには大学のSSO認証が必要。
- 追加の本人確認や二要素認証を求められることがある。方法はアカウントの設定によって異なる。リカバリーコードが表示されたら安全な場所に保管する。分からなければ授業担当者か管理者に尋ねる。

### 試しのリポジトリ

- 作成先（Owner）にtokyo-city-universityを選ぶ。
- 名前は`ats-名字-test-1`の形式（例：名字がtanakaなら`ats-tanaka-test-1`）。名字のローマ字が分からなければ授業担当者に尋ねる。
- 公開設定はPrivate（授業担当者の指示どおり）。

### うまくいかないとき

- リポジトリがアプリの一覧に出ない：ブラウザでリポジトリを開けるか、作成先と名前が正しいかを確かめ、SSOのURLで認証をやり直し、アプリを再起動する。
- 「Access denied」「Single sign-on to view this chat.」と出る：その組織へのSSOのセッションがない。SSOのURLで大学アカウントの認証をし、アプリに戻って再読み込みする。
- それでも直らなければ、画面のメッセージを記録して授業担当者か管理者に連絡する。

### そのほか

- ブラウザ版のCopilot Chat（`https://github.com/copilot`）も使える。SSO認証が済んでいれば、組織のリポジトリを文脈に選べる。
- チャットへの質問の例が挙げられている（リポジトリの構成の説明、README.mdの作成、授業メモのひな形、コードの問題点の説明など）。Copilotがファイルの作成や変更を提案したら、内容を確かめてから実行・保存する。
- 利用上の注意：回答には誤りがありうる。大学や授業で扱いが許されていない情報を入力しない。リポジトリはPrivateで作る。
- 授業開始時の確認項目として、サインイン、SSO認証、組織へのアクセス、リポジトリの作成と命名、Private設定、アプリの起動とサインイン、リポジトリを開く、チャットで質問、の9項目が挙げられている。

### 資料から分からないこと

大学の組織の公開範囲の選択肢（Internalなど）、二要素認証の具体的な方式、プランの期間と学期後の扱い、アプリのポリシーの状態、学内ネットワークの制限。
