# 資料：git worktreeの公式ドキュメント（Git）

Gitの公式ドキュメント「git-worktree」を、ワークツリーの考え方と基本の操作を知る目的で読んだ結果の要約です（2026年11月2日に確認）。

## 資料の情報

- git-worktree：[https://git-scm.com/docs/git-worktree](https://git-scm.com/docs/git-worktree)
- 発行者：Gitプロジェクト（公式）
- 確認した日：2026年11月2日
- 種類：ウェブ上の資料（エージェントが調べたもの。`raw/`の資料ではない）

## 内容の要約

- ワークツリー（worktree）は、既存のリポジトリにつながったもう一つの作業用ディレクトリ。再びクローンしたり、作業中の変更を退避したりせずに、複数のブランチを同時に取り出して作業できる。
- クローンやinitで作られる最初のものがメインのワークツリー。`git worktree add`で足したものがリンクされたワークツリー。
- ブランチ、タグ、オブジェクト（履歴の中身）、リポジトリの設定は全ワークツリーで共有される。HEADとインデックス（次のコミットに入れる変更の一覧）はワークツリーごとに別になる。
- 基本の操作：`git worktree add`（追加）、`git worktree list`（一覧）、`git worktree remove`（削除）。
- 一つのブランチは同時に一つのワークツリーでしか取り出せない。コミットしていない変更があるワークツリーは、強制しない限り削除できない。メインのワークツリーは削除できない。
- 公式は、複数のチェックアウトの機能を実験的なものとし、サブモジュールへの対応は不完全と説明している。
