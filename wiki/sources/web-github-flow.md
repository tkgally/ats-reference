# 資料：GitHub flow（GitHub Docs）

## 内容の要約

- GitHub flowは、ブランチを軸にした軽い作業の流れ。開発者だけでなく誰にとっても役に立つとされ、GitHub自身も利用規約、ドキュメント、ロードマップに使っている。必要なのはGitHubのアカウントとリポジトリ。全ての手順をウェブの画面、コマンドライン、GitHub Desktopのどれでも行える。
- 流れ：（1）ブランチを作る。名前は短く内容が分かるものにする。既定のブランチに影響を与えずに作業できる。（2）ブランチで変更する。間違えても元に戻せ、マージするまで既定のブランチには入らない。（3）変更をコミットしてpushする。各コミットには内容が分かるメッセージを付け、一つのコミットには一つの完結した変更を入れるのが理想。pushすると作業が遠隔の保管場所に退避され、他の人からも見える。関係のない変更ごとにブランチを分ける。（4）プルリクエストを作り、フィードバックを求める。早めに意見がほしいときはドラフトにできる。概要と、何を解決するかを書く。課題（Issue）とリンクすると、マージ時にIssueが自動で閉じられる。（5）レビューに応じて変更する。（6）チェックが通り、承認されたらマージする。（7）使い終わったブランチを削除する。
- リポジトリによっては、プルリクエストに自動のチェックが走り、承認のレビューが必須になる。
