# GitHubの認証：トークンとSSHキー

ターミナルなどのコマンドラインからGitHubのリポジトリを使うときに、パスワードの代わりになる「個人用アクセストークン」と「SSHキー」についてのページです。

## 背景

GitHubの画面（ブラウザー）には、ユーザー名とパスワード、二要素認証でサインインします。一方、自分のパソコンのGitからGitHubへ変更を送る（[プッシュ](push-pull-fetch.md)）ときは、別の方法で本人であることを示す必要があります。その方法が、次の二つです（[資料：GitHubの個人用アクセストークンとSSH](../sources/web-github-pat-ssh.md)、2026年11月6日に確認）。

この授業ではGitHub Copilotデスクトップアプリが中心で、多くの受講生はこの設定を自分でしなくてすむと思われます（資料外の補足）。ターミナルでGitを使う場合や、認証のエラーが出た場合に役立ててください。

## 個人用アクセストークン

- 役割：パスワードの代わりに使う文字列。Gitで`https://`の形のリモートを使うとき、パスワードを聞かれたらトークンを入力する。
- 権限：自分のアカウントの権限を、トークンの設定の範囲に絞ったもの。アカウントの権限を超えることはない。
- 種類：細かく設定できる「fine-grained」が推奨されている。対象を自分または一つの組織、特定のリポジトリ、必要な権限だけに絞れる。もう一つの「classic」は、アクセスできるすべてのリポジトリに及ぶので、より危険。
- 作る場所：GitHubのプロフィール画像から、Settings、Developer settings、Personal access tokensの順に進む。
- 有効期限：fine-grainedの既定は30日。期限を付けることが強く勧められている。
- 扱い方：パスワードと同じように扱う。人に教えない。リポジトリにファイルとして入れない（[.gitignore](gitignore.md)で除くだけでなく、そもそも書き込まない）。不要になったら削除する。

## SSHキー

- 役割：トークンの入力なしで、リポジトリを使えるようにする。`git@github.com:`で始まる形のリモートで使う。
- 仕組み：二つで一組の鍵を作る。秘密鍵は自分のパソコンに置き、誰にも見せない。公開鍵だけをGitHubのアカウントに登録する。
- 扱い方：秘密鍵にパスフレーズを付ける。登録した鍵を定期的に見直し、使わない鍵や漏れた疑いのある鍵は取り消す。

## どちらを使うか

どちらも、一度設定すれば毎回の入力を省けます。トークンはHTTPSのリモートでのみ、SSHキーはSSHのリモートでのみ使えます。リポジトリのクローンのときにどちらの形のURLを選んだかで決まります（[クローン](clone.md)）。公式は、トークンを作る前にGitHub CLIやGit Credential Managerで足りないかを考えるよう勧めています。初心者には、デスクトップアプリかVS Codeのサインイン機能に任せるのが簡単と思われます（資料外の補足）。

## 授業の組織で使うとき

授業の組織はSSOでつながっているので、トークンとSSHキーは、組織ごとに認可しないと組織のリポジトリに使えません。認可していないと、組織のリポジトリだけ認証に失敗します（[シングルサインオン（SSO）](single-sign-on.md)）。組織が承認を求める設定のとき、fine-grainedのトークンは承認されるまで公開情報しか読めません。授業の組織の設定は未確認です（要確認）。
