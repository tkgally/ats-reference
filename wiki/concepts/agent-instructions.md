# エージェントへの指示ファイル

AIエージェントが作業の前に読む、リポジトリの中の約束事のファイル（`AGENTS.md`、Copilotのカスタム指示など）についてのページです。

## 指示ファイルとは

AIエージェントは、会話のたびに前提を一から説明されなくても済むよう、リポジトリに置かれた決まった名前のファイルを読んで、そこに書かれた約束事に従って作業できます。プロジェクトの目的、ファイルの置き場所、文章の書き方、作業の手順などを一度書いておけば、使うたびに同じことを頼み直す必要がありません（資料外の補足）。毎回のやりとりで使う頼み方（[プロンプト](prompt.md)）に対して、指示ファイルは「いつも前提にしてほしいこと」をリポジトリに残しておく仕組みと考えると分かりやすいです。

## GitHub Copilotが読むファイル

GitHubとVS Codeの公式ドキュメントによると、Copilotはリポジトリの次のファイルを指示として読みます（2026年10月7日に確認、[資料：Copilotが読む指示ファイル](../sources/web-github-copilot-instructions.md)）。

- `.github/copilot-instructions.md`：リポジトリ全体への指示。
- `.github/instructions/`の中の`*.instructions.md`：特定のファイルだけに当てはまる指示。
- `AGENTS.md`：エージェントへの指示。リポジトリのどこに置いてもよく、複数あるときは、作業しているファイルから見て最も近いものが優先される。
- `CLAUDE.md`か`GEMINI.md`：リポジトリの最上位に置けば、`AGENTS.md`の代わりに使える。

指示が重なったときの優先順位は、個人の指示、リポジトリの指示、組織の指示の順です。VS CodeのCopilotも`AGENTS.md`を読み、設定（`chat.useAgentsMdFile`）で読むかどうかを切り替えられます。Copilotデスクトップアプリで同じように読まれるかは、資料では確かめていません（要確認）。

## 共通のファイル名にする利点

エージェントごとに指示ファイルの名前が違うと、複数のツールを使うプロジェクトでは同じ約束事を何度も書くことになります。このリポジトリでは、約束事を`AGENTS.md`にまとめ、エージェント独自のファイル（`CLAUDE.md`など）には「`AGENTS.md`に従うこと」とだけ書いています（[AGENTS.md](../../AGENTS.md)）。授業では複数のAIツールを使うので、こうしておけば、どのツールでも同じ約束事で作業できます（[資料：授業の背景情報](../sources/ats-class-background.md)）。

## 何を書くか

次の例は、このリポジトリの`AGENTS.md`を手本にした書き方の案です（資料外の補足）。

- 目的と読者：何のためのプロジェクトで、誰が読むのか。
- 構成：どのフォルダーに何があり、エージェントが変更してはいけないのはどれか。
- 書き方の規則：言語、文体、ファイル名の付け方。
- 作業の手順：作業の始め方と終え方、確認のコマンド、コミットやプルリクエストの流れ。
- 人間に確認してほしいこと：推測で進めずに聞くべき場面。

長すぎると読み落とされやすくなるので、守ってほしいことに絞って書き、運用しながら直していくのがよいでしょう（資料外の補足）。

## 注意

- 指示ファイルの内容は、リポジトリを見られる人にも見えます。パスワードやトークンなどの秘密を書かない（[GitHubの認証：トークンとSSHキー](github-authentication.md)）。
- エージェントが指示を必ず守る保証はありません。重要な変更は人間が確認します（[エージェントの承認と権限](agent-permissions.md)、[ハルシネーション](hallucination.md)）。
