# GitHub flow（ブランチとプルリクエストの流れ）

ブランチを作って変更し、プルリクエストでレビューを受けてから本流に取り込む、GitHubの標準的な作業の流れ、GitHub flowについてのページです。

## 流れ

GitHub公式のドキュメントによれば、GitHub flowはブランチを軸にした軽い作業の流れで、開発者だけでなく誰にとっても役に立ちます（[資料：GitHub flow](../sources/web-github-flow.md)、2026年10月9日に確認）。

1. ブランチを作る：短く内容が分かる名前を付ける。既定のブランチ（ふつうは`main`）に影響を与えずに作業できる。
2. 変更する：ブランチの上で間違えても、元に戻したり直したりできる。マージするまで既定のブランチには入らない。
3. コミットしてpushする：各コミットには内容が分かるメッセージを付ける。一つのコミットには一つの完結した変更を入れるのが理想。pushすると作業が遠隔に退避され、共同作業者にも見える。関係のない変更は別のブランチに分ける。
4. プルリクエストを作る：変更の概要と、何を解決するかを書く。早めに意見がほしいときはドラフトにできる。
5. レビューを受けて直す。
6. チェックが通り、承認されたらマージする。
7. 使い終わったブランチを削除する。

リポジトリによっては、プルリクエストに自動のチェックが走ったり、承認のレビューが必須になったりします。

## このリポジトリでの例

この知識ベースのリポジトリでも、AIエージェントが作業用のブランチで変更し、プルリクエストを作り、サイト組み立ての自動チェック（GitHub Actions）が通ってから`main`に取り込みます（[AGENTS.md](../../AGENTS.md)）。授業のプロジェクトでも同じ流れを使えます（資料外の補足）。
