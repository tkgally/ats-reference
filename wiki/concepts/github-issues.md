# Issues

プロジェクトの作業や疑問を書き留め、話し合い、進み具合を追うためのGitHubのしくみ、Issues（課題）についてのページです。

## Issuesとは

GitHub公式のドキュメントによれば、Issuesはリポジトリの中で作業を計画し、話し合い、追跡するためのしくみです。不具合の報告、機能の要望、アイデア、作業項目など、書き留めたり話し合ったりしたい話題に使えます（[資料：IssuesとREADME](../sources/web-github-issues-readme.md)、2026年10月12日に確認）。

## 付けられる情報

- 担当者：だれが取り組んでいるかを示す。
- ラベル、課題の種類、マイルストーン：課題を分類し、目標ごとにまとめる。
- サブ課題：大きな作業を小さく分ける。
- 依存関係：どの課題がほかの作業を止めているか（または待っているか）を示す。

## ほかの作業とのつながり

課題を別の課題やプルリクエストの中で言及すると、相互の参照ができます。プルリクエストの説明に特定のキーワードを書くと、マージされたときに関連する課題が自動で閉じます（[GitHub flow](github-flow.md)）。GitHub Projectsと連携して、チームの作業を一覧で追うこともできます。

## 授業での使いどころ

授業でIssuesを使うと決まった資料はありません。チームでプロジェクトを進めるときに、やることの一覧や、AIエージェントへの依頼の記録として使えると思われます（資料外の補足）。
