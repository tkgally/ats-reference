# ワークツリー

一つのリポジトリから、複数のブランチを別々のフォルダーに同時に取り出して作業できる仕組み、ワークツリー（worktree）についてのページです。

## ワークツリーとは

ワークツリーは、既存のリポジトリにつながった、もう一つの作業用フォルダーです。ふつうはブランチを切り替えると、一つのフォルダーの中身がそのブランチの状態に入れ替わります。ワークツリーを使うと、ブランチごとに別のフォルダーを持てるので、作業中の変更を退避したり、もう一度クローンしたりせずに、複数のブランチを同時に開いておけます（[資料：git worktree](../sources/web-git-docs-worktree.md)、2026年11月2日に確認）。

- メインのワークツリー：クローンなどで最初にできるフォルダー。削除できない。
- リンクされたワークツリー：`git worktree add`で足したフォルダー。
- 共有されるもの：ブランチ、タグ、履歴の中身、リポジトリの設定。
- ワークツリーごとに別のもの：今どのブランチ（またはコミット）を取り出しているか、コミット前の変更の一覧。

## 基本の操作

- `git worktree add ../hotfix`：新しいフォルダーを作り、その中で作業する。
- `git worktree list`：ワークツリーの一覧を見る。
- `git worktree remove ../hotfix`：使い終わったフォルダーを削除する。

注意点は次のとおりです。

- 一つのブランチは、同時に一つのワークツリーでしか取り出せない。
- コミットしていない変更があるワークツリーは、強制しない限り削除できない。
- 公式は、この機能のうち複数のチェックアウトを実験的なものとしている。

## Copilotデスクトップアプリとの関係

GitHub Copilotデスクトップアプリでは、エージェントのセッションを始めるときに、変更を入れる場所として「New worktree」か「Current checkout」を選べると、公式ドキュメントの要約にあります（2026年10月30日に確認、[資料](../sources/web-github-copilot-app-agent-sessions.md)）。「New worktree」は別の作業用コピーで作業する選択肢なので、エージェントの作業が今開いているフォルダーに影響しません。アプリがこの選択肢の裏でGitのワークツリーを使っているかどうかは、資料に書かれていません（要確認）。
