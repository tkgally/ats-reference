# Markdown

記号だけで見出しや箇条書きなどの書式を付けられる文章の書き方、Markdownについてのページです。

## Markdownとは

Markdownは、フォントの大きさや色のような凝った変更はせず、キーボードの記号だけで最低限の書式を付ける書き方です。どの端末でもきれいに表示されます（[資料：Markdown Reference](../sources/web-commonmark-help.md)、2026年10月9日に確認）。このWikiのページも、解説サイトのもとになる文章も、Markdownで書かれています。

## 主な書き方

- 見出し：行頭に`#`を置く。個数が多いほど小さい見出しになる。
- 箇条書き：行頭に`-`または`*`を置く。番号付きは`1.`。
- リンク：`[表示名](URL)`。画像は`![説明](URL)`。
- 引用：行頭に`>`。
- コード：短いものは`` ` ``で囲み、複数行は`` ``` ``で囲む。

詳しい規則は公式の仕様（CommonMark）にあります。

## GitHubでの書き方の注意

GitHubは、基本の書き方に加えて独自の機能を使えます（[資料：GitHubの基本的な書式](../sources/web-github-markdown-syntax.md)、2026年10月21日に確認）。

- 取り消し線：`~~`で囲む。
- タスクリスト：`- [ ] 項目`と`- [x] 項目`で、未完了と完了のチェックリストを作る。
- 見出しへのリンク：`[表示名](#見出しのアンカー)`。アンカーは見出しを小文字にし、空白をハイフンにして作られる。見出しを書き換えるとアンカーも変わるので、リンクも直す。
- 隠しコメント：`<!-- 内容 -->`は表示されず、ソースにだけ残る。
- 注意書き：引用の先頭に`[!NOTE]`や`[!WARNING]`などを書くと、目立つ囲みになる。多用は勧められていない。
- 記号をそのまま見せる：記号の前にバックスラッシュを置く。
- 改行の違い：課題やプルリクエストでは1回の改行がそのまま改行になるが、`.md`ファイルでは空行を入れないと段落が分かれず、1回の改行では改行にならない。このWikiが段落を1行で書くのはこのためでもある（日本語の途中で改行すると、表示で半角の空白が入る）。
- 表：GitHubは表も表示できるが、書き方はこの資料に載っていない（資料外の補足：`|`で列を区切る書き方がよく使われる）。

## このWikiでの約束

日本語の文章では、斜体・太字の記号が括弧や句読点と隣り合うと正しく表示されないことがあります。そのため、このWikiでは太字・斜体を使わず、段落の途中で改行もしません。詳しくは[AGENTS.md](../../AGENTS.md)の「日本語で書くための規則」にあります。
