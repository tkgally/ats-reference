# .gitignore（無視するファイル）

コミットしたくないファイルをGitに伝えるための設定ファイル、`.gitignore`についてのページです。

## .gitignoreとは

`.gitignore`は、Gitがコミットの対象にしないファイルやフォルダーを列挙するファイルです。パソコンの中の一時ファイルや、リポジトリに入れたくないファイルを、うっかりコミットしないために使います。`.gitignore`自体をコミットすると、リポジトリをクローンした人とも同じ規則を共有できます（[資料：.gitignore、ライセンス、GitHub Pages](../sources/web-github-gitignore-license-pages.md)、2026年10月17日に確認）。

## 作り方

リポジトリのフォルダーでターミナルを開き、`touch .gitignore`を実行すると空のファイルができます。中身は、無視したいファイルの名前や場所を一行ずつ書きます。OS、言語、環境ごとのひな型が、GitHubの`github/gitignore`リポジトリやgitignore.ioで配られています。規則の書き方は次の節にまとめます。

## 規則の書き方

次の内容は、Gitの公式ドキュメントにもとづきます（[資料：gitignoreの規則の書き方](../sources/web-git-docs-gitignore.md)、2026年10月19日に確認）。

- 空行は何にも一致しません。`#`で始まる行はコメントです。行の途中からのコメントは書けません。
- `*.log`のように、`*`は`/`以外の任意の文字列に、`?`は1文字に一致します。`[a-z]`は範囲内の1文字に一致します。
- `/`を含まない規則（`tmp`など）は、どの階層のファイルやフォルダーにも一致します。行頭に`/`を付けた規則（`/build`）は、`.gitignore`のあるフォルダーの直下だけを指します。
- 行末に`/`を付けた規則（`tmp/`）は、フォルダーだけに一致します。
- 行頭に`!`を付けた規則は、前の規則で無視されたものを対象に戻します。ただし、親のフォルダーが無視されていると、中のファイルは戻せません。
- `logs/**/debug.log`のように`**`を使うと、間に何階層あってもかまいません。
- 同じ段階の中では、最後に一致した規則が結果を決めます。深いフォルダーの`.gitignore`は、浅いフォルダーのものより優先されます。

書き方の例です。

```
# ログファイルは無視するが、keep.logは残す
*.log
!keep.log

# 最上位のbuildフォルダーを無視する
/build/

# どの階層のtmpフォルダーも無視する
tmp/
```

## 注意すること

- すでにコミットされて追跡されているファイルは、`.gitignore`に書き足しても無視されません。先に`git rm --cached ファイル名`で追跡をやめる必要があります。
- すべてのリポジトリで無視したいもの（エディターのバックアップなど）は`~/.config/git/ignore`に、自分だけで使う規則は、リポジトリの中の`.git/info/exclude`に書けます。
- パスワードや鍵のような秘密の情報は、公式ドキュメントのこのページでは扱われていません。すでにコミットしてしまった情報は履歴に残ります（資料外の補足）。そもそもリポジトリに入れないことが大切です。
