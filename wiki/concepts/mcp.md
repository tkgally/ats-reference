# MCP（Model Context Protocol）

AIアプリケーションを、ファイル、データベース、ほかのサービスなどの外部のシステムにつなぐための共通の約束ごと、MCP（Model Context Protocol）についてのページです。

## MCPとは

MCPは、AIアプリケーションと外部のシステムをつなぐ方法を決めたオープンソースの標準です。公式はUSB-Cにたとえています。USB-Cが機器をつなぐ共通の差し込み口であるように、MCPはAIアプリを外部のデータや道具につなぐ共通の方法になります（[資料：MCPの紹介とアーキテクチャ](../sources/web-mcp-intro-architecture.md)、2026年11月3日に確認）。

共通の方法があるので、一度作った接続の部品を、MCPに対応した多くのアプリ（Claude、ChatGPT、Visual Studio Codeなど）で使えます。これにより、[AIエージェント](ai-agent.md)が、カレンダーを見る、デザインのデータを読む、データベースにたずねるといった作業を、さまざまなサービスに対して行えるようになります。

## 登場するもの

- MCPホスト：MCPを使うAIアプリケーション。Claude CodeやVS Codeなど。
- MCPクライアント：ホストの中で、一つのサーバーとの接続を受け持つ部分。サーバー一つにつき一つ作られる。
- MCPサーバー：文脈（データや機能）を提供するプログラム。自分のパソコンで動くもの（ローカル）も、ネット上で動くもの（リモート）もある。

サーバーが提供できるものは、おもに次の三つです。

- ツール：AIが呼び出して実行できる機能（ファイルの操作、外部サービスへの要求、データベースへの問い合わせなど）。
- リソース：AIに文脈として渡すデータ（ファイルの内容、データベースの記録など）。
- プロンプト：やり取りの型を決める、再利用できるひな形。

MCPが決めるのは情報のやり取りの約束だけです。AIアプリがLLMをどう使うか、受け取った文脈をどう扱うかは、アプリの側が決めます。

## 使うときの注意

MCPサーバーはAIにファイルの読み書きや外部サービスの操作をさせる入り口になるので、信頼できないサーバーをつなぐと、不具合や悪意の影響を受けるおそれがあります。VS Codeの公式ドキュメントの要約でも、第三者のMCPサーバーを危険の一つに挙げ、設定を確かめてから信頼するよう勧めています（[エージェントの承認と権限](agent-permissions.md)）。つなぐ前に、提供元と、サーバーに許す操作の範囲を確かめてください。
