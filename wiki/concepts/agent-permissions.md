# エージェントの承認と権限

AIエージェントが、ファイルの編集や命令の実行などをするときに、人間がどこまで確認し、どこまで任せるかを決める仕組み、承認と権限についてのページです。

## なぜ大事か

エージェントは、人間のパソコンの上で、人間と同じ権限でファイルを書き換えたり命令を実行したりできます（[AIエージェント](ai-agent.md)）。VS Codeの公式ドキュメントは、主な危険として次を挙げています（2026年10月26日に確認、[資料：VS Codeの承認と権限、Workspace Trust](../sources/web-vscode-approvals-trust.md)）。

- プロンプトインジェクション：取得したウェブページなどに紛れた悪意ある指示で、エージェントの作業が乗っ取られる。
- 自動の操作：ファイルの編集、命令の実行、外部サービスの操作が、確認なしに進む。
- 第三者の拡張機能やMCPサーバーの不具合や悪意。
- 秘密の情報の流出：ファイルの内容やターミナルの出力は、文脈としてモデルに送られる。

## 承認の仕組み（VS Code）

VS Codeでは、エージェントが道具を使う前に、人間に確認を求めます。表示された入力内容を確かめてからAllowを選びます。変えたいときは、拒否して、エージェントに直す点を伝えます。

権限のレベルは、チャット入力欄のメニューで切り替えます。

- Manual permissions（既定）：自動承認の設定に合うもの以外は、毎回確認する。
- Assisted permissions（試験的）：LLMが各操作を審査し、承認しないものだけ確認する。
- Allow all：すべてを確認なしで実行する。
- Autopilot：道具の承認も、エラーのやり直しも、止まる質問への回答も自動で行う。

公式ドキュメントは、Allow allとAutopilotは壊す恐れのある操作の確認を省くので、信頼できるワークスペースでだけ使うよう警告しています。ターミナルの命令の自動承認も、助けにはなるが安全の境界ではないとされています。

## 承認の仕組み（Copilotデスクトップアプリ）

授業で使うCopilotデスクトップアプリにも、ツールを実行する前の確認があります。公式ドキュメントによれば、セッションのモード（対話型、プラン、Autopilot）と、ツールの権限は別の設定です（2026年10月28日に確認、[資料：Copilotアプリのツールの権限とサンドボックス](../sources/web-github-copilot-app-permissions.md)）。

- Manual approval（Ask every time）：ツールの実行前に毎回確認する。
- Assisted：モデルが各要求を審査し、安全と判断したものは自動で承認し、そうでないものだけ人に確認する。
- Unconditional approval（Approve all）：確認なしで実行する。

切り替えは、プロンプト欄の下のモードの表示からTool permissionsを選ぶと、そのセッションだけ変わります。ローカルのセッションの既定は、アプリの設定の「Sessions」で決めます。VS Codeの三つのレベル（Manual、Assisted、Allow all）とほぼ対応していますが、設定名や画面は同じではありません。どのレベルが最初の既定かは、資料には書かれておらず未確認です。

公式ドキュメントは、Assistedではモデルが間違えて危険な操作を承認する恐れがあり、サンドボックスの代わりにはならないと注意しています。組織の管理者は、Approve allとAssistedの両方を使えなくできます（大学の組織の設定は不明）。

## サンドボックス

ローカルのサンドボックスは、エージェントが実行するツールが触れるファイル、通信、認証情報を制限する仕組みです。承認の手順とは別のもので、既定ではオフです。Copilotデスクトップアプリでは、`/sandbox on`でそのセッションをオンにできます。使わないと、エージェントの命令は自分と同じ権限で動きます。クラウドのサンドボックスは、セッション全体をGitHubの用意した隔離環境で動かし、使った量に応じて課金されます（授業で使えるかは未確認）。

## 信頼できるフォルダーだけで動かす（Workspace Trust）

見慣れないフォルダーをVS Codeで開くと、作者を信頼するかを尋ねられます。信頼しないとRestricted Modeになり、AIエージェント、ターミナル、タスク、デバッグが止まります。文章の閲覧と編集はできます。コマンドパレットの「Workspaces: Manage Workspace Trust」で、信頼の状態を変えられます。親のフォルダーを信頼すると、その下のフォルダーすべてが信頼されます。

他人のリポジトリを`clone`して開くときは、中身を確かめるまでRestricted Modeのままにするのが安全です（資料外の補足：授業のリポジトリやチームのリポジトリのように、作者が分かっているものは信頼してよいと思われるが、授業としての方針は資料がなく要確認）。

## 初心者向けの心がけ

公式ドキュメントの対策を、授業の状況に当てはめたものです。

- 最初は既定のManual permissionsのまま使い、承認の表示の中身を読む習慣をつける。
- エージェントが変えたファイルは、コミットの前に差分で確かめる（[コミット](commit.md)）。
- `.env`など秘密の情報を含むファイルをエージェントに触らせない。パスワードやAPIキーをリポジトリに置かない。
- Allow allとAutopilotは、壊れても困らない試しのリポジトリだけで使うか、使わない（資料外の補足）。
- 拡張機能は、信頼できる発行元のものだけを入れる。

## 確認が必要な点

- Copilotデスクトップアプリ（[GitHub Copilotデスクトップアプリ](../tools/github-copilot-app.md)）の権限の既定のレベル、許可を求める画面の細部、フォルダーを信頼するかを尋ねる仕組み（Workspace Trustに当たるもの）の有無は、資料に書かれておらず未確認。（2026年10月26日時点では、VS Codeと同じかどうか不明としていたが、公式ドキュメントで権限のレベルは確かめられた。）
- 組織（大学）の設定で、権限のレベルが制限されるかは分からない。
- 設定名は変わることがある。取得内容は要約を通したため、実際の画面で確かめること。
