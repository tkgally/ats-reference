プロジェクトが形になってきたら、リポジトリの「身だしなみ」を整えましょう。他の人（チームの仲間、先生、発表を聞いた人）がリポジトリを開いたとき、何のプロジェクトで、どう使えばよいかが分かるようにするためです。このページでは、最上位に置いておきたい三つのファイルと、ウェブサイトとして公開するGitHub Pagesを説明します。公式の情報は2026年10月17日にWikiの資料として確かめたものにもとづきます。

## READMEで入り口を作る

READMEは、リポジトリを開いたときに最初に表示される説明のファイルです。GitHubの公式ドキュメントによれば、プロジェクトの目的、役立つ点、始め方、助けを得る方法、維持している人を書きます。訪問者が最初に目にするので、使い始めるために必要なことに絞り、長い説明は別のページに置きます。書式は[Markdownの書き方](markdown.md)のとおりで、ファイル名は`README.md`にします。

<div class="box tip" markdown="1">
<p class="box-title">AIに下書きを頼む</p>

READMEの下書きはAIが得意です。「このリポジトリのファイルを読んで、READMEの案を作って。目的、使い方、作った人の順に」のように頼み、できた文章は自分で読んで、事実と違うところを直します。[AIの答えを確かめる](checking-ai-output.md)の約束は、ここでも同じです。

</div>

## .gitignoreでコミットしないものを決める

`.gitignore`は、Gitがコミットの対象にしないファイルやフォルダーを一行ずつ書いておくファイルです。パソコンの一時ファイルなど、リポジトリに入れたくないものをうっかりコミットしないために使います。このファイル自体をコミットすると、リポジトリをクローンした人とも同じ規則を共有できます。

- 作り方：リポジトリのフォルダーで`touch .gitignore`を実行すると空のファイルができる。AIのエージェントに「この言語向けの.gitignoreを作って」と頼んでもよい。
- ひな型：OS、言語、環境ごとのひな型が、GitHubの`github/gitignore`リポジトリなどで配られている。
- すでにコミットしたファイルには効かない：追跡されているファイルは、書き足しても無視されない。先に`git rm --cached ファイル名`で追跡をやめる必要がある。この命令を打つときは、[ターミナル入門](terminal-basics.md)の確かめ方を使い、何が起きるかを理解してから許可する。

<div class="box danger" markdown="1">
<p class="box-title">秘密の情報は、そもそも入れない</p>

パスワードやAPIキーのような秘密の情報を一度コミットすると、履歴に残ります。`.gitignore`に書き足しても、過去の履歴からは消えません（GitHubのこのページでは扱われていない、資料外の補足です）。秘密の情報は、最初からリポジトリに入れないことが大切です。もし入れてしまったら、一人で抱えずに、すぐ教員やTAに相談してください。

</div>

## ライセンスで使ってよい範囲を示す

ライセンスは、他の人がコードや文章を使い、変更し、配布してよい範囲を示すものです。リポジトリにライセンスがないと、著作権法の既定が適用され、作者がすべての権利を持ちます。つまり、リポジトリを公開しても、他の人は複製も、配布も、改変もできません。

- 置き方：ライセンスの本文を、リポジトリの最上位に`LICENSE.txt`、`LICENSE.md`、`LICENSE.rst`のいずれかの名前で置く。READMEで触れるだけにせず、ファイルを置くよう勧められている。
- 選ぶ画面：新しいリポジトリを作るときにだけ出る。既存のリポジトリには、ブラウザーでファイルを追加する。
- 種類：GitHubの一覧には、MIT、Apache License 2.0、GPLなどがある。選び方は、[choosealicense.com](https://choosealicense.com/)が紹介されている。
- 法的な疑問：GitHubは法律事務所ではないので、専門家に相談するよう書かれている。

授業のリポジトリは、当面Privateで作る指示が出ています（[GitHub](../../../wiki/tools/github.md)）。Privateのままなら、ライセンスを急ぐ必要はありません。公開するときは、AIが作った文章や画像、他の人の資料の権利にも気をつけ、ライセンスを決めてください（[AIを使うときの倫理とルール](ai-ethics.md)）。授業としての決まりは、いまのところ資料がありません。

## GitHub Pagesでサイトとして公開する

GitHub Pagesは、HTML、CSS、JavaScriptのファイルをリポジトリから公開する、静的サイトのサービスです。このガイドも、この形で公開されています（[このサイトの使い方](about-this-site.md)）。公開先は、プロジェクトのサイトなら`https://<アカウント名>.github.io/<リポジトリ名>`です。

- 公開すると、URLを知った人は誰でも見られると考えておく（資料外の補足）。個人情報や、学内限定の資料は載せない。
- 利用できないもの：オンラインの事業、電子商取引、商用のSaaSの無料ホスティング。パスワードやクレジットカード番号を扱う用途にも使わない。
- 目安：公開するサイトは1GBまで、通信量は月100GB、ビルドは1時間に10回。
- 訪問者のIPアドレスは、安全のために記録される。
- 大学の組織のリポジトリで使えるか、公開範囲がどうなるかは、まだ分かっていません。使いたいときは、先に教員に確かめてください。

実際に公開する手順（`docs/`フォルダーから公開する方法と、GitHub Actionsで公開する方法）は、[GitHub Pagesで自分のサイトを公開する](github-pages.md)で一歩ずつ説明しています。

## 公開の前の確認

- READMEに、目的と使い方が書いてあるか。
- `.gitignore`で、不要なファイルが入らないようになっているか。秘密の情報は入っていないか。
- ライセンスを決めたか（Privateのままなら後でよい）。
- 他の人の著作物や個人情報が、許可なく入っていないか。
- 公開してよいと、チームで話し合ったか（[チームでプロジェクトを進める](teamwork.md)）。
