## チャットとエージェントの違い

ChatGPTやCopilotのチャットに質問すると、AIは文章で答えを返します。答えを読んで、ファイルに書き写したり、言われたとおりに操作したりするのは人間です。

AIエージェント（AI agent）は、そこから一歩進んで、AIが自分で作業を進めるしくみです。人は「この資料をWikiに取り込んで」のように目標を伝えます。エージェントは、ファイルを開いて読み、書き換え、命令を実行し、結果を確かめ、うまくいかなければやり直しながら、目標に向かって作業を続けます。エージェント（agent）は「代理人」という意味で、人の代わりに手を動かしてくれる存在だと考えると分かりやすいでしょう。

<figure class="fig">
{{svg:ai-agents-chat-vs-agent.svg}}
<figcaption>チャットでは、答えをもとに手を動かすのは人。エージェントでは、AIが道具を使って作業し、人は目標を決めて結果を確かめる。</figcaption>
</figure>

| | チャット | エージェント |
| :---- | :---- | :---- |
| 人が伝えるもの | 質問 | 目標（してほしい作業） |
| AIが返すもの | 答えの文章 | 作業の結果と報告 |
| ファイルの書き換え | 人がする | AIがする |
| やりとりの回数 | 一問一答が基本 | AIが自分で何度も試す |
| 人の役割 | 答えを読み、使うかどうか決める | 目標を決め、操作を許可し、結果を確かめる |

どちらが優れているということではありません。調べものや相談はチャット、まとまった作業はエージェント、と使い分けます。チャットのAIのしくみは[大規模言語モデルのしくみ](how-llms-work.md)で説明しています。

## エージェントが動くしくみ：ループ

エージェントの中で考えているのは、チャットと同じ大規模言語モデル（LLM）です。違うのは、モデルの外側に「道具」と「繰り返しのしくみ」が付いていることです。エージェントは、目標に届くまで、次のループ（輪）を何度も回ります。

<figure class="fig">
{{svg:ai-agents-loop.svg}}
<figcaption>エージェントは、計画、行動、観察、判断のループを、目標に届くまで繰り返す。終わったら人に報告し、人が結果を確かめる。</figcaption>
</figure>

- ① 計画する：目標を達成するために、次に何をするかを考える。
- ② 道具を使う：ファイルを読む、書き換える、命令を実行する、ウェブを調べる、などの行動をとる。
- ③ 結果を見る：行動の結果（ファイルの中身、命令の出力、エラーの文など）を読む。
- ④ 判断する：目標に届いたかを考える。まだなら①に戻り、届いたら人に報告する。

たとえば「`raw/`に置いた授業のメモをWikiに取り込んで」と頼んだとき、エージェントの中ではこんなことが起きています。

<ol class="steps">
<li>指示ファイル（<code>AGENTS.md</code>）を読み、取り込みの手順を確かめる。</li>
<li>メモを読み、目録（<code>wiki/index.md</code>）を読んで、関係しそうなページを探す。</li>
<li>要約ページを新しく作り、関係するページを書き換える。</li>
<li>書き換えたページを読み直し、リンクが正しいか、約束事を守っているかを確かめる。間違いを見つけたら直す。</li>
<li>目録と作業記録を更新し、何をしたかを人に報告する。</li>
</ol>

人が一つずつ指示しなくても、エージェントは結果を見ながら次の一手を決めていきます。これが、チャットとのいちばん大きな違いです。

## エージェントが使う道具

エージェントにどんな道具が渡されているかで、できることが決まります。よく使われる道具には、次のようなものがあります。

| 道具 | できること | 例 |
| :---- | :---- | :---- |
| ファイルの読み書き | リポジトリやフォルダーの中のファイルを開いて読み、作り、書き換える。 | 要約ページを作る、リンクを直す |
| ターミナル（コマンドの実行） | 文字で命令を打ち込む画面で、プログラムを動かす。 | Gitでコミットする、サイトを組み立てて確かめる |
| ウェブの検索と取得 | 検索エンジンで調べたり、ウェブページを読んだりする。 | 公式の案内で最新の料金を確かめる |
| 外部のサービスとの接続 | GitHub、カレンダー、文書管理など、ほかのサービスを操作する。MCP（Model Context Protocol）という共通の接続方法が広く使われている。 | Issueを作る、プルリクエストにコメントする |

道具が増えるほど、エージェントは多くのことをできるようになります。同時に、間違えたときの影響も大きくなります。どの道具を、どこまで使わせるかを決めるのは人の役目です。

## いろいろなAIエージェント

2026年10月時点では、多くの会社がAIエージェントを提供しています。代表的なものを挙げますが、名前、機能、料金は変わりやすいので、使う前に公式の案内を確かめてください。

| エージェント | 提供元 | 主に使う場所 |
| :---- | :---- | :---- |
| GitHub Copilot（エージェントモード、クラウドエージェント） | GitHub | VS Code、github.com |
| Claude Code | Anthropic | ターミナル、エディター、デスクトップアプリ、ウェブ |
| Codex | OpenAI | ターミナル、エディター、ウェブ |
| Gemini CLI | Google | ターミナル |

この授業では、大学の予算で提供されるGitHub Copilotがいちばん身近なエージェントになります（[GitHub Copilot](../../../wiki/tools/github-copilot.md)）。Copilotのエージェントの使い方は[Copilotのエージェントに作業を頼む](copilot-agent.md)で説明します。ほかのツールとの比べ方は[AIツールの比べ方](ai-tools-compare.md)を見てください。

## 指示ファイル：エージェントへの約束事

エージェントは、作業を始めるときに、リポジトリの中にある指示ファイルを読みます。指示ファイルには、そのリポジトリの目的、ファイルの置き方、書き方の規則、作業の手順など、毎回守ってほしいことを書いておきます。人間の職場でいえば、新しく来た人に渡す「業務マニュアル」のようなものです。

指示ファイルの名前は、エージェントによって違うことがあります（2026年10月時点）。

- `AGENTS.md`：特定の製品に限らず、多くのエージェントが読む共通の名前。GitHub CopilotやOpenAI Codexはこの名前のファイルを読む。
- `CLAUDE.md`：Claude Codeが読むファイルの名前。
- そのほか、`GEMINI.md`（Gemini CLI）や`.github/copilot-instructions.md`（Copilot専用）など、製品ごとの名前もある。

この授業の知識ベースでは、約束事を`AGENTS.md`一つにまとめ、`CLAUDE.md`などの製品ごとのファイルには「`AGENTS.md`に従うこと」とだけ書いています（[AGENTS.md](../../../AGENTS.md)）。こうしておくと、どのエージェントを使っても同じ約束事で作業でき、約束事を変えるときも一か所を直せば済みます。授業では一つの製品に頼らず、複数のAIツールを比べながら使うことを目指しているので、このようにエージェントに依存しない作り方をしています（[LLM Wiki](../../../wiki/concepts/llm-wiki.md)、[第2回（2026年10月7日）：GitHubのデモ](../../../wiki/course/sessions/session-02.md)）。

<div class="box tip" markdown="1">
<p class="box-title">ポイント</p>

自分のプロジェクトのリポジトリにも、`AGENTS.md`を一つ置いておきましょう。「このリポジトリは何のためのものか」「日本語で書く」「どのフォルダーに何を置くか」の3点を書くだけでも、エージェントの作業がぐっと安定します。

</div>

## 人が関わるところ（ヒューマン・イン・ザ・ループ）

エージェントに任せるといっても、すべてを任せきりにするわけではありません。人がループの中の要所に関わることを、ヒューマン・イン・ザ・ループ（human-in-the-loop）と言います。エージェントを安全に使うために、人は次の3か所で関わります。

### 1. 許可：何をしてよいかを決める

多くのエージェントは、ファイルを書き換える前や、命令を実行する前に、人に許可を求めます。表示された内容を読み、問題がなければ許可し、分からなければ止めて質問します。すべての操作を自動で許可する設定もありますが、慣れないうちは使わないほうが安全です。

### 2. レビュー：結果を確かめる

エージェントが「完了しました」と言っても、本当に正しくできているとは限りません。変更された内容（差分）を読み、頼んだとおりになっているか、頼んでいないことをしていないかを確かめます。確かめ方は[AIの出力を確かめる](checking-ai-output.md)で説明します。

### 3. バージョン管理：失敗しても戻れるようにする

GitHubのようなバージョン管理（変更の履歴を残すしくみ）は、エージェントを使うときの安全網になります。作業の前の状態がコミットとして残っていれば、エージェントが失敗しても元に戻せます。ブランチで作業させ、プルリクエストで確かめてから取り込めば、本流（`main`）を壊す心配もありません（[GitHubとは：基本の考え方](github-basics.md)、[ブランチとプルリクエストでの共同作業](github-collaboration.md)）。

## 限界とリスク

エージェントは強力な道具ですが、次のような限界とリスクがあります。

- もっともらしい間違い：大規模言語モデルは、事実と違うことを自信ありげに書くことがある。エージェントの場合、その間違いがファイルに書き込まれ、ほかのページにも広がることがある。
- 「できた」と言ってしまう：作業が途中なのに、完了したと報告することがある。
- 頼んでいないことをする：目標に向かう途中で、関係のないファイルを書き換えたり、勝手に作業の範囲を広げたりすることがある。
- 外からの指示に乗せられる：エージェントが読んだウェブページやファイルに「これまでの指示を無視して〜せよ」のような文が紛れ込んでいると、それに従ってしまうことがある（プロンプトインジェクションと呼ばれる）。出どころの分からない資料を読ませるときは特に注意する。
- 秘密の漏れ：エージェントはリポジトリの中のファイルを読むので、パスワードや個人情報を置いておくと、それがAIのサービスに送られる。
- 使える量と費用：エージェントは何度もループを回るので、チャットよりも多くの量（AIクレジットなど）を使う。
- 自分の学びが減る：何でも任せると、自分で考える機会が減る。何を任せ、何を自分でするかを意識して決める。

そして、エージェントが作ったものでも、それを使ったり公開したりする責任は人にあります。レポートや発表でAIを使ったときのルールは、[AIを使うときの倫理とルール](ai-ethics.md)と[AI利用の倫理](../../../wiki/concepts/ai-ethics.md)を確かめてください。
