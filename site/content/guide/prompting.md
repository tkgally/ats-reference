## プロンプトとは

AIに送る頼みや質問の文章を「プロンプト」と呼びます。同じAIでも、プロンプトの書き方しだいで、答えの質は大きく変わります。

AIへの頼み方は、初めて会う、とても物知りで仕事の速いアシスタントに仕事を頼むときと似ています。そのアシスタントは、あなたのこと、あなたのプロジェクトのこと、先生に何を求められているかを、何も知りません。頼まれたことには一生懸命に応えますが、書かれていないことは推測で補います。推測が外れると、的外れな答えになります。

プロンプトのコツは、特別な呪文ではありません。人に仕事を頼むときに伝えるべきことを、省かずに伝えることです。

## よい頼み方の五つの要素

よいプロンプトには、次の五つの要素が入っています。全部を毎回書く必要はありませんが、答えが期待と違ったときは、どれかが欠けていないかを見直してみましょう。

<figure class="fig">
{{svg:prompting-anatomy.svg}}
<figcaption>よいプロンプトの例を、要素ごとに色分けしたもの。目的、背景、条件、出力の形、資料がそろっている。</figcaption>
</figure>

- 目的：何のために、何をしてほしいのか。「調べて」「書いて」だけでなく、それを何に使うのかも書く。
- 背景：自分は誰で、どんな状況にいるのか。読み手は誰か。すでに分かっていること、決まっていることは何か。
- 条件：守ってほしいこと。字数、期限、予算、使ってはいけないもの、文体（です・ます調か、である調か）など。
- 出力の形：答えをどんな形でほしいか。箇条書き、表、手順、メールの文面、案をいくつ出すか、など。
- 資料と例：判断の材料になる資料や、「こんな感じで」という見本。

## 資料を渡す、例を見せる

AIの知識はあいまいで、古いこともあります（[生成AIのしくみ](how-llms-work.md)）。正確さが大事なときは、もとになる資料をプロンプトに貼り付けるか、ファイルとして添付して、「この資料にもとづいて答えて」と頼みます。資料に書かれていないことは「資料には書かれていない」と答えるよう頼んでおくと、AIが推測で話を作るのを防ぎやすくなります。

文章の調子や形式を伝えたいときは、言葉で説明するより、見本を見せるほうが確実です。「次の例と同じ形で書いて」として、一つか二つの例を示します。

```
次の例と同じ形式で、残りの3冊についても紹介文を書いてください。

例：
書名：『〇〇』
ひとことで：〜〜な本
おすすめの読者：〜〜な人
```

## 大きな仕事は分けて頼む

レポートを丸ごと一度に頼むと、全体がぼんやりした答えになりがちです。大きな仕事は、段階に分けて頼みましょう。たとえば次のように進めます。

1. テーマについて、調べるべき問いを挙げてもらう。
2. 問いを選び、構成（見出しの案）を作ってもらう。
3. 見出しごとに、自分で調べた資料を渡して下書きを手伝ってもらう。
4. 全体を読み直して、分かりにくい箇所を指摘してもらう。

一つ一つの段階で答えを確かめ、方向を修正できるので、最後に大きく外れることがなくなります。計算や推理が必要な問題では、「一歩ずつ考えて」「結論の前に理由を書いて」と頼むのも効果があります。

## AIに質問してもらう

自分でも何を頼めばよいか分からないときは、AIに質問してもらうのが有効です。プロンプトの最後に次のように書き足します。

```
答える前に、よい答えを出すために必要な情報を、私に質問してください。
質問は一度に3つまでにしてください。
```

AIの質問に答えていくうちに、自分のしたいことがはっきりしてきます。企画を考える、テーマを絞る、といった最初の段階で特に役立ちます。

## 役割を与える

「あなたは〇〇の専門家です」のように、AIに役割を与える書き方もよく知られています。役割を与えると、答えの観点や言葉づかいが変わります。

- 「高校の先生として、この説明が高校生に分かるか確かめてください。」
- 「審査員として、この企画書の弱い点を3つ指摘してください。」
- 「この分野の初心者として、分からない言葉を挙げてください。」

ただし、役割を与えただけで、AIの知識が増えたり、正確になったりするわけではありません。役割は「どの立場から見てほしいか」を伝える方法と考え、資料や条件を渡すことと組み合わせましょう。

## やりとりを重ねてよくする

最初の答えが完璧であることはまれです。プロンプトは一度で決めるものではなく、やりとりを重ねてよくしていくものです。

<figure class="fig">
{{svg:prompting-cycle.svg}}
<figcaption>頼む、読む、確かめる、直す点を決める、のくりかえしで答えをよくしていく。</figcaption>
</figure>

直してほしい点を伝えるときは、「もっとよくして」ではなく、具体的に伝えます。

## そのまま使える型

よく使う場面ごとに、プロンプトの型を用意しました。コピーして、【 】の部分を書き換えて使ってください。

### 調べものをする

```
【テーマ】について調べています。
目的は【授業のプロジェクトで、〜を決めるため】です。
私は【大学1年生で、この分野は初めて】です。

次の形で答えてください。
1. 全体像を、高校生にも分かる言葉で300字程度で説明
2. 知っておくべき重要な点を5つ
3. 詳しく調べるための信頼できる情報源（公式サイト、公的機関など）

不確かなことは「不確か」と書いてください。
情報源には、実在を確かめられるURLだけを挙げてください。
```

### 企画を立てる

```
【プロジェクトの内容】の企画を立てています。

条件：
- メンバー：【人数、得意なこと】
- 期間：【〜月〜日まで】
- 使えるもの：【予算、道具、AIツール】

まず、企画を具体的にするために必要な質問を3つしてください。
私が答えたら、週ごとの計画を表にしてください。
```

### 文章を直してもらう

```
次の文章は【誰に向けた、何のための文章】です。
【分かりやすさ／論理の流れ／敬語】の観点から、直すべき点を指摘してください。

- 書き直した全文ではなく、直す点と理由を箇条書きで示してください。
- 私の言いたいことや結論は変えないでください。

【文章を貼り付ける】
```

### エージェントに作業を頼む

GitHub Copilotのエージェントなど、ファイルを読み書きできるAIに作業を頼むときの型です（[AIエージェントとは](ai-agents.md)、[Copilotのエージェントに作業を頼む](copilot-agent.md)）。

```
このリポジトリは【何のためのもの】です。
まずAGENTS.mdとREADME.mdを読んでください。

やってほしいこと：
【例：docs/の中の議事録を読み、決まったことをdecisions.mdにまとめる】

守ってほしいこと：
- 【既存のファイルは消さない】
- 【日本語の書き方はAGENTS.mdの規則に従う】
- 作業の前に、どのファイルをどう変えるかの計画を見せてください。
- 終わったら、変えたことを短く報告してください。
```

<div class="box warn" markdown="1">
<p class="box-title">注意</p>

型を使っても、AIの答えが正しいとは限りません。とくに事実、数字、出典、プログラムは、必ず確かめてから使いましょう（[AIの答えを確かめる](checking-ai-output.md)）。また、他人の個人情報や公開してはいけない資料は、プロンプトに入れないでください。

</div>

## 日本語で頼むときのコツ

最近のAIは日本語をよく理解しますが、日本語ならではの注意点もあります。

- 主語と目的語を省かない：日本語は「誰が」「何を」を省きがちだが、AIは文脈から推測して取り違えることがある。「私たちのチームが」「この企画書の」のように書く。
- 「いい感じに」「適当に」「よしなに」を避ける：人どうしなら通じる言葉も、AIには基準が伝わらない。何がよいかを具体的に書く。
- 文体を指定する：「です・ます調で」「である調で」「話し言葉で」などと書くと、そろった文章になる。
- 字数は目安と考える：「400字程度」と書けば長さの目安になるが、AIは字数を正確に数えるのが苦手なので、できた文章の字数は自分で確かめる。
- 表記をそろえる：固有名詞や専門用語の表記（「ユーザー」か「ユーザ」か、など）を指定しておくと、あとの手直しが減る。
- 英語の情報も使う：プログラミングや最先端の研究など、英語の情報が多い分野では、「英語の資料も調べて、日本語でまとめて」と頼むと、答えが充実することがある。
- 改行に注意する：多くのチャット画面では、<span class="ui">Enter</span>キーで送信される。プロンプトの途中で改行したいときは、<span class="ui">Shift</span>＋<span class="ui">Enter</span>を使う（ツールによって異なる）。

丁寧な言葉で頼んでも、くだけた言葉で頼んでも、答えの質に大きな差はありません。自分が書きやすい言葉で、具体的に書くことのほうが大切です。

<div class="box try" markdown="1">
<p class="box-title">やってみよう</p>

自分のプロジェクトについて、まず一行だけの短いプロンプトで頼んでみましょう。次に、このページの五つの要素（目的、背景、条件、出力の形、資料）を足したプロンプトで同じことを頼み、答えを比べてみましょう。最後に、プロンプトの最後に「答える前に私に質問してください」と足すと、どう変わるかも試してみましょう。

</div>
