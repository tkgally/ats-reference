## GitHubは「ファイルと履歴の置き場」

GitHub（ギットハブ）は、ファイルと、そのファイルがどう変わってきたかの記録（履歴）を、インターネット上に保管して共有するためのサービスです。もともとはプログラマーがソースコードを管理するために使うものですが、文章、資料、画像、データなど、どんなファイルでも置けます。この授業では、プロジェクトのファイル、知識ベース、作業の記録を置く場所として使います（[GitHub](../../../wiki/tools/github.md)）。

似たサービスにGoogleドライブやOneDriveがありますが、GitHubには次のような違いがあります。

- 変更のたびに「何を、なぜ変えたか」の説明つきで記録が残る。
- いつでも前の状態を見たり、元に戻したりできる。
- 複数の人やAIエージェントが、同じファイルを壊さずに並行して作業できるしくみがある。
- AIエージェントが読み書きしやすい。エージェントがした変更も、一つずつ確かめられる。

## 覚えておきたい5つの言葉

GitHubの画面は英語です（2026年10月時点）。まずは次の5つの言葉を覚えれば、画面の大部分が読めるようになります。英語の画面の言葉をもっと知りたいときは[英語の画面を読むための単語帳](github-english-ui.md)を見てください。

| 言葉 | 英語の画面での表記 | 意味 |
| :---- | :---- | :---- |
| リポジトリ | <span class="ui">Repository</span> | プロジェクトのファイルと履歴をまとめた箱。略して「リポ」とも言う。 |
| コミット | <span class="ui">Commit</span> | ファイルの変更を、説明をつけて履歴に記録すること。また、その記録の一つ一つ。 |
| ブランチ | <span class="ui">Branch</span> | 本流（main）から枝分かれした作業用の流れ。試しに変えてみるときに使う。 |
| プルリクエスト | <span class="ui">Pull request</span> | ブランチでの変更を本流に取り込んでほしいという依頼。略して「PR」。 |
| マージ | <span class="ui">Merge</span> | ブランチでの変更を本流に合流させること。 |

## コミット：変更を記録する

GitHubで一番大切なのはコミットです。ファイルを書き換えたら、それを「コミット」して履歴に記録します。コミットには、変更の内容を短く説明する文（コミットメッセージ）を付けます。

<figure class="fig">
{{svg:github-commits.svg}}
<figcaption>コミットは時間の流れに沿って積み重なる。それぞれのコミットは、その時点のファイル全体の記録になっている。</figcaption>
</figure>

コミットメッセージは、あとで履歴を見たときに「この変更は何だったか」が分かるように書きます。日本語で書いてかまいません。

AIエージェントに作業を頼んだ場合は、エージェントがコミットメッセージも書いてくれます。メッセージを読めば、エージェントが何をしたかを確かめられます。

## 履歴：いつでも前の状態に戻れる

コミットが積み重なったものが履歴です。GitHubのリポジトリの画面で、ファイル一覧の上にある時計のアイコンと<span class="ui">Commits</span>という表示をクリックすると、履歴の一覧が開きます。一つ一つのコミットを開くと、どの行がどう変わったかが、削除は赤、追加は緑で表示されます。

履歴があるので、AIエージェントに大胆な変更を頼んでも、うまくいかなければ前の状態に戻せます。「失敗しても戻れる」ことが、AIと一緒に作業するうえでの大きな安心材料になります。

<div class="box tip" markdown="1">
<p class="box-title">ポイント</p>

こまめにコミットするほど、戻れる地点が増えます。一つのコミットには、一つのまとまった変更（「企画書の第2節を書いた」など）を入れるのがよいとされています。

</div>

## ブランチとプルリクエスト：安全に変更を試す

リポジトリには、本流となる`main`というブランチがあります。大きな変更を試すときや、AIエージェントに作業を任せるときは、`main`から枝分かれしたブランチを作り、そこで作業します。作業が終わったら、プルリクエストを出して変更の内容を確認し、問題がなければ`main`にマージします。

この授業の知識ベースも、エージェントがブランチで作業し、プルリクエストを通じて`main`に取り込む、という流れで更新されています。詳しくは[ブランチとプルリクエストでの共同作業](github-collaboration.md)で説明します。

## GitとGitHubの違い

Git（ギット）は、ファイルの変更履歴を記録するための道具（ソフトウェア）の名前です。GitHubは、Gitで記録したリポジトリをインターネット上に置いて共有するためのサービスです。GitHubの画面やAIエージェントを使えば、Gitの命令を自分で打つ必要はほとんどありません。ただ、エージェントが作業の説明で「git commit」「git push」などと言うことがあるので、次の対応を知っておくと便利です。

- `git commit`：変更を履歴に記録する（コミット）。
- `git push`：自分のパソコンやエージェントの作業場所にあるコミットを、GitHubに送る。
- `git pull`：GitHubにある新しいコミットを、自分の側に取ってくる。
- `git clone`：GitHubのリポジトリを、丸ごと自分の側に複製する。

## 公開と非公開

リポジトリには、だれでも見られる公開（<span class="ui">Public</span>）と、招待した人しか見られない非公開（<span class="ui">Private</span>）があります。作るときに選び、あとから設定で変えることもできます。

<div class="box warn" markdown="1">
<p class="box-title">注意</p>

公開のリポジトリには、個人情報（自分や他人の氏名と学籍番号、連絡先など）、パスワードやAPIキー、公開してはいけない資料を置かないでください。一度公開してコミットした内容は、あとで消しても履歴に残ります。迷ったら非公開にしておき、教員に相談しましょう（[AIを使うときの倫理とルール](ai-ethics.md)）。

</div>
