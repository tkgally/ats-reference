## なぜ確かめる必要があるのか

生成AIは、事実と違うことを、もっともらしく自信ありげに答えることがあります。これを「ハルシネーション」（幻覚）と呼びます。AIは「正しい答え」ではなく「もっともらしい続きの文章」を作るしくみなので、正しい答えを知らないときでも、それらしい文章を書けてしまうのです（[生成AIのしくみ](how-llms-work.md)）。

やっかいなのは、AIの言い方からは、正しいか間違っているかが見分けにくいことです。人なら、自信がないときは口ごもったり「たぶん」と言ったりしますが、AIは正しい答えも間違った答えも、同じように流暢な文章で返します。

<figure class="fig">
{{svg:checking-ai-output-confidence.svg}}
<figcaption>AIの答えは、正しくても間違っていても、たいてい自信のある言い方で出てくる。言い方の自信は、正しさの手がかりにならない。</figcaption>
</figure>

AIの答えをプロジェクトの成果物、レポート、発表、知識ベースに使うなら、その内容に責任を持つのは、AIではなく使った人です。確かめる習慣を身につけましょう。

## よくある間違いの種類

AIの間違いには、いくつかの典型があります。種類を知っておくと、どこを確かめればよいかが分かります。

| 種類 | 例 | 確かめ方 |
| :---- | :---- | :---- |
| 架空の出典 | 実在しない本や論文、存在しないURLを挙げる | 出典を実際に開く、検索する |
| 事実の誤り | 人名、年、数字、統計、地名を取り違える | 一次資料と照らし合わせる |
| 古い情報 | 料金、制度、製品の機能が以前のまま | 日付と公式の案内を確かめる |
| 計算と数え間違い | 合計、割合、字数、日数を間違える | 電卓や表計算で計算し直す |
| 動かないコード | 存在しない命令や部品を使う、一部しか動かない | 実際に動かして試す |
| 資料の読み違い | 要約に資料にないことを足す、逆の意味に取る | 元の資料の該当箇所を読む |
| 迎合 | 利用者の思い込みに合わせて、間違いに同意する | 反対の立場からも聞いてみる |

最後の「迎合」は見落とされがちです。「〇〇は△△ですよね？」と聞くと、AIは「はい、そのとおりです」と答えやすい傾向があります。確かめたいときは、「〇〇について、賛成と反対の両方の根拠を挙げて」のように、答えを誘導しない聞き方をしましょう。

<div class="box warn" markdown="1">
<p class="box-title">特に注意：架空の出典</p>

AIが挙げる参考文献やURLは、もっともらしいのに実在しないことがあります。著者名、題名、雑誌名、年がそろっていても、組み合わせが架空ということもあります。AIが挙げた出典は、自分で開いて内容を読むまで、レポートに書かないでください。

</div>

## 確かめる方法

AIの答えを確かめるときの流れは、おおむね次のとおりです。すべての答えを同じ手間で確かめる必要はありません。どれだけ大事な用途に使うかで、確かめる深さを決めます。

<figure class="fig">
{{svg:checking-ai-output-flow.svg}}
<figcaption>大事な用途に使う答えは、内容の種類ごとにふさわしい方法で確かめ、確かめた結果を記録してから使う。</figcaption>
</figure>

### 一次資料に当たる

一次資料とは、情報の出どころそのものです。統計なら官公庁の発表、制度なら法律や公式の案内、製品なら作った会社の公式サイト、研究なら論文そのものが一次資料です。AIの答えも、ウェブのまとめ記事も、一次資料ではありません。大事な事実と数字は、一次資料で確かめましょう。

### 出典を求め、実際に開く

AIに「この答えの根拠となる情報源を示して」と頼むと、出典を挙げてくれます。ウェブ検索を使えるAIなら、リンクつきで答えてくれます。ただし、出典が付いていることと、出典の内容が答えを支えていることは別です。リンクを開いて、次の点を確かめます。

- そのページは実在し、信頼できる発信元のものか。
- ページの中に、AIの答えと同じことが本当に書かれているか。
- そのページはいつのものか。古くなっていないか。

### 別の方法で照らし合わせる

同じ質問を別のAIにもしてみる、検索エンジンで調べる、教科書や図書館の本を見る、詳しい人に聞く、などの方法で照らし合わせます。答えが一致すれば信頼度は上がり、食い違えば、そこが確かめるべき箇所です。ただし、複数のAIが同じ間違いをすることもあるので、AIどうしの一致だけで安心しないようにしましょう。

### プログラムは動かして試す

AIが書いたプログラムは、読んで正しそうに見えても、動かすとエラーになることがあります。また、動いても、想定していない入力で失敗することがあります。プログラムは必ず実際に動かし、いくつかの入力で結果を確かめます。エージェントにプログラムを書かせるときは、「動作を確かめるテストも書いて、実行して」と頼むのも有効です（[AIエージェントとは](ai-agents.md)）。

### 日付を確かめる

AIの知識には締め切りがあり、検索した記事も古いことがあります。料金、ツールの機能、制度、日程、人の役職など、時間とともに変わる情報は、いつの時点の情報かを必ず確かめます。記録するときは「2026年10月時点」のように時点も書きましょう。

## 危ない答えのチェックリスト

次のような答えは、間違いを含んでいる可能性が高いので、特に注意して確かめましょう。

- 具体的な数字、日付、人名、引用が多いのに、出典が示されていない。
- 出典のURLを開くと、ページが見つからない、または内容が違う。
- 最新の出来事や、ごく最近の製品・制度について、検索を使わずに答えている。
- 地域限定の情報、小さな組織、あまり知られていない人物について、詳しく答えすぎている。
- 自分が期待していたとおりの答えで、都合がよすぎる。
- 同じ質問をし直すと、違う答えが返ってくる。
- 指摘すると、すぐに「申し訳ありません」と別の答えに変わる（どちらが正しいか、AI自身も分かっていない可能性がある）。
- プログラムに、見たことのない命令や部品の名前が出てくる。

<div class="box tip" markdown="1">
<p class="box-title">ポイント</p>

AIに「この答えのうち、確信が持てない部分はどこですか」「間違っている可能性がある箇所を挙げてください」と聞くと、確かめるべき箇所の見当がつくことがあります。ただし、この答えも完全ではありません。最後は自分で確かめましょう。

</div>

## 確かめる手間をかける場所

すべての答えを一次資料で確かめるのは大変です。用途に応じて、手間のかけ方を変えましょう。

- 軽く確かめれば十分なもの：アイデア出し、文章の言い回しの案、自分が内容をよく知っている文章の要約など。おかしなところがないか読めばよい。
- しっかり確かめるもの：レポートや発表に書く事実と数字、引用、出典、他人に関わる情報、知識ベースに書き込む内容、公開するプログラム。

知識ベースのように、あとから何度も参照される場所に書く内容は、特にしっかり確かめます。一度まぎれこんだ間違いは、後の作業にも引き継がれてしまうからです（[自分のプロジェクトに知識ベースを作る](knowledge-base.md)）。

## AIを使ったことを記録する

プロジェクトでAIを使ったら、どのように使ったかを記録しておきましょう。記録は、チームでの共有、成果の振り返り、発表での説明に役立ちます。また、どこまでが自分たちの考えで、どこからがAIの出力かを示すことは、AIを誠実に使うための基本でもあります（[AIを使うときの倫理とルール](ai-ethics.md)）。

記録しておくとよいのは次の項目です。

- 日付
- 使ったツール（ChatGPT、Claude、Gemini、Copilotなど。分かればモデル名も）
- 何に使ったか（調査、案出し、文章の推敲、プログラムなど）
- 頼んだ内容の要点（プロンプトそのものか、その要約）
- AIの出力をどう使ったか（そのまま、手直しして、参考にしただけ）
- 何をどう確かめたか

GitHubのリポジトリで作業しているなら、作業記録のファイル（たとえば`log.md`）に追記していくのが手軽です。この授業の知識ベースでも、作業の記録を`wiki/log.md`に残しています。

```
## 2026-10-21 AIの利用記録
- ツール：Claude（無料版）
- 用途：アンケートの質問案を10個出してもらった
- 使い方：案を参考に、チームで6問に絞って書き直した
- 確かめたこと：質問の言葉が誘導的でないか、チーム全員で読んだ
```

レポートや発表資料で、AIの出力を引用したり、AIの助けを借りたことを示したりするときの具体的な書き方は、授業での指示や、提出先の決まりに従ってください。決まりが分からないときは、教員に確認しましょう。

<div class="box try" markdown="1">
<p class="box-title">やってみよう</p>

使っているAIに「生成AIと教育について書かれた日本語の本を3冊、著者名と出版年つきで挙げてください」と頼んでみましょう。次に、挙がった本が実在するか、著者名と出版年が正しいかを、図書館の蔵書検索や書店のサイトで確かめてみましょう。ウェブ検索を使う場合と使わない場合で、結果を比べるのもおすすめです。

</div>
