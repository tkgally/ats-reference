AIエージェントは、道具を使って作業を進めます。その道具を、アプリごとに別々の方法でつなぐのは大変です。そこで作られたのが、MCP（Model Context Protocol）という共通の約束です。公式の情報は2026年11月3日に確かめたものにもとづきます（[資料：MCPの紹介とアーキテクチャ](../../../wiki/sources/web-mcp-intro-architecture.md)）。

## MCPとは

MCPは、AIアプリを外部のシステムにつなぐ方法を決めた、オープンソースの標準です。公式は「AIアプリのUSB-Cポート」にたとえています。USB-Cが機器をつなぐ共通の差し込み口であるように、MCPは、AIアプリとデータや道具をつなぐ共通の差し込み口になります。

共通の約束があるので、一度作った接続の部品を、MCPに対応した多くのアプリ（Claude、ChatGPT、Visual Studio Codeなど）で使い回せます。公式が挙げる例には、AIがカレンダーを見る、デザインのデータからウェブアプリを作る、組織のデータベースにチャットでたずねる、などがあります。

## 三つの登場人物

<figure class="fig">
{{svg:mcp-host-client-server.svg}}
<figcaption>ホストの中に、サーバーごとのクライアントができる。サーバーは手元でもネット上でも動く。</figcaption>
</figure>

- MCPホスト：MCPを使うAIアプリ。Claude CodeやVS Codeなど。
- MCPクライアント：ホストの中にあって、一つのサーバーとの接続を受け持つ部分。サーバー一つにつき一つ作られる。利用者が意識することはあまりない。
- MCPサーバー：データや機能を提供するプログラム。自分のパソコンで動くものも、ネット上で動くものもある。

「サーバー」という名前ですが、大きな機械とは限りません。自分のパソコンで動く小さなプログラムもサーバーと呼ばれます。

## サーバーが出せる三つのもの

| 種類 | 意味 | 例 |
| :---- | :---- | :---- |
| ツール | AIが呼び出して実行できる機能 | ファイルを操作する、外部のサービスに要求を送る、データベースにたずねる |
| リソース | AIに文脈として渡すデータ | ファイルの内容、データベースの記録 |
| プロンプト | やり取りの型を決める、再利用できるひな形 | 「議事録を要約する」ときの決まった頼み方 |

MCPが決めるのは、情報をやり取りする約束だけです。AIがLLMをどう使うか、受け取った情報をどう扱うかは、AIアプリの側が決めます。

## 使う前の注意

<div class="box warn" markdown="1">
<p class="box-title">信頼できるサーバーだけをつなぐ</p>

MCPサーバーは、AIにファイルの読み書きや外部サービスの操作をさせる入り口になります。信頼できないサーバーをつなぐと、不具合や悪意の影響を受けるおそれがあります。

- つなぐ前に、提供元を確かめる。
- そのサーバーに許す操作の範囲を確かめる。
- 個人情報や、公開してはいけないものを扱うサーバーは、とくに慎重に選ぶ。

</div>

VS Codeの公式ドキュメントも、第三者のMCPサーバーを危険の一つに挙げ、設定を確かめてから信頼するよう勧めています（[エージェントの承認と権限](../../../wiki/concepts/agent-permissions.md)）。AIにどこまで任せるかの考え方は、[AIエージェントとは](ai-agents.md)と[Copilotデスクトップアプリを使い始める](copilot-app.md)の「ツールの権限とサンドボックス」も参考にしてください。

## この授業では

この授業の資料には、MCPを使う手順は出てきません。Copilotデスクトップアプリで、授業の組織がMCPサーバーを使えるかどうかは未確認です（要確認）。まずは「AIエージェントが外の道具を使うときの共通の仕組みがある」ことを知っておけば十分です。
