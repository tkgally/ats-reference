プルリクエストを作ると、画面に緑のチェックや赤い×が出ることがあります。あれは、GitHubが自動で作業を行った結果です。この自動化の仕組みを、GitHub Actions（ギットハブ・アクションズ）といいます。仕組みを細かく覚える必要はありませんが、何が起きているかが分かれば、確認が赤くなっても落ち着いて対処できます。公式の情報は2026年11月1日に確かめたものにもとづきます（[資料：GitHub Actionsの基本](../../../wiki/sources/web-github-actions-overview.md)）。

## GitHub Actionsでできること

GitHub Actionsは、リポジトリで何かが起きたときに、決めておいた作業を自動で行います。たとえば次のようなことです。

- プルリクエストが作られるたびに、テストやリンク切れの確認を走らせる。
- 変更が`main`に取り込まれたら、サイトを組み立てて公開し直す。
- 新しいIssueに、自動でラベルを付ける。

人が毎回手作業でやると忘れたり間違えたりすることを、機械に任せるための仕組みです。

## 五つの部品

GitHub Actionsの説明には、次の五つの言葉が出てきます。

- ワークフロー：自動化された一連の処理の全体。リポジトリの`.github/workflows`フォルダーに置くYAMLという形式のファイルで書く。
- イベント：ワークフローを動かすきっかけ。プルリクエストの作成、Issueの作成、プッシュなど。手動や、決めた時刻に動かすこともできる。
- ジョブ：同じ場所で実行される手順のまとまり。ふつうはジョブどうしが並んで動き、順番を指定すれば前のジョブが終わるのを待つ。
- アクション：繰り返し使える部品。リポジトリの取得や環境の準備などを、自分で書かずに呼び出せる。
- ランナー：実際に処理を行うサーバー。GitHubが用意するLinux、Windows、macOSの仮想マシンで、実行のたびに新しい環境で動く。

設定がリポジトリの中のファイルに書かれるので、自動化の手順そのものも、コミットの履歴として残ります。

## このリポジトリでの使われ方

この授業の知識ベースのリポジトリにも、「サイトの公開」というワークフローがあります（[`.github/workflows/pages.yml`](https://github.com/tkgally/ats-reference/blob/main/.github/workflows/pages.yml)）。

- プルリクエストが作られると、サイトを組み立て、リンク切れがないかを確かめる。
- 確認が通ったプルリクエストが`main`に取り込まれると、GitHub Pagesに公開し直す。

つまり、このサイトを読んでいるあなたの画面は、GitHub Actionsが組み立てて公開したものです。公開の方法は[GitHub Pagesで自分のサイトを公開する](github-pages.md)にあります。Wikiの説明は[GitHub Actions](../../../wiki/concepts/github-actions.md)にまとめてあります。

## 確認が赤くなったら

<div class="box try" markdown="1">
<p class="box-title">やってみよう：赤い×を見たときの手順</p>

1. プルリクエストの画面で、赤い×の横にある <span class="ui">Details</span> を開く。
2. 失敗した手順（赤くなっている行）を開き、エラーのログを読む。
3. ログをそのままAIエージェントに貼り、「この確認が失敗した原因と直し方を教えて」と日本語で頼む。
4. 直したらコミットしてプッシュする。確認は自動でもう一度走る。

</div>

ログは英語で長く見えますが、たいていは最後のほうに原因が書かれています。ログに個人情報やパスワードが含まれていないかは、貼る前に確かめてください（[AIに貼り付ける前の確認](ai-ethics.md)）。

<div class="box warn" markdown="1">
<p class="box-title">確認を黙らせない</p>

確認が通らないからといって、確認そのものを消したり飛ばしたりするのは避けましょう。確認は、公開前に問題を見つけるための仕組みです。エージェントに「確認を通して」と頼むときは、「確認を消さずに、原因を直して」と添えてください。

</div>

## 覚えておくこと

- ワークフローの書き方を覚える必要はありません。必要になったら、エージェントに日本語で頼めば書いてもらえます。ただし、できあがったファイルは、何をするものか説明してもらってから採用しましょう。
- 自動で動く処理には、プランやリポジトリの設定によって使える量の上限がある場合があります。授業の組織での扱いは未確認です。
- 画面の表記（Detailsなど）は、公式の説明にもとづくものです。実際の画面での確認はまだです。
