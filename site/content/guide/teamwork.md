チームで取り組むと、一人ではできない大きなテーマに挑めます。その一方で、「だれが何をするのか分からない」「話したはずのことが伝わっていない」といったすれ違いも起きやすくなります。このページは、チームで進めるときに人と人のあいだで必要になることをまとめたものです。GitHubの操作は[ブランチとプルリクエストでの共同作業](github-collaboration.md)で説明しています。

「AIとの探検ゼミナール」では、個人でもチームでもプロジェクトに取り組めます（[授業の概要](../../../wiki/course/course-overview.md)）。チームの作り方、人数、評価の方法は、2026年10月15日時点でWikiに資料がありません。授業での案内に従ってください。チームで意見を交わして成果を高めることは、達成目標の「協働力」にも当たります（[達成目標](../../../wiki/course/learning-goals.md)）。

## チームがうまくいかなくなる理由

<figure class="fig">
{{svg:teamwork-cycle.svg}}
<figcaption>チームの進め方の一巡。決める、分ける、進める、持ち寄る、振り返るを繰り返す。</figcaption>
</figure>

すれ違いの多くは、次のどれかから起こります。

- ゴールの食い違い：同じテーマでも、メンバーがそれぞれ違う完成形を思い描いている。
- 担当のあいまいさ：同じ作業を二人がしてしまう。だれもしていない作業が残る。
- 伝わっていない：口頭で決めたことが、その場にいなかった人に届いていない。
- 言い出しにくさ：遅れや困りごとを、言いにくくて黙ってしまう。

どれも、最初に少し話し合い、決めたことを書いておくだけで減らせます。

## 最初の話し合いで決めること

最初の集まりで、次の5つを話し合います。30分ほどで足ります。

<ol class="steps">
<li>ゴール：このプロジェクトで何を作り、だれの何に役立てるのか。一文で言えるようにする。</li>
<li>範囲：期間内にできることと、やらないこと。</li>
<li>役割：だれが何を受け持つか（次の節）。</li>
<li>連絡と集まり：連絡する場所、集まる時間、返事の目安（例：丸1日以内）。</li>
<li>困ったとき：遅れそうなときは早めに伝える、意見が割れたらどう決めるか。</li>
</ol>

決めたことは「チームの約束」として、リポジトリの`README.md`か`team.md`のようなファイルに書いておきます。次のような短い書き方で十分です。

```
# チームの約束

- ゴール：大学周辺の防災情報を、留学生にも読みやすくまとめたページを作る。
- やらないこと：多言語の自動翻訳アプリを作ること。
- 役割：Aさん＝調べもの、Bさん＝文章、Cさん＝図と公開。毎週交代して見直す。
- 連絡：相談はGitHubのIssueに書く。返事は1日以内。
- 遅れそうなとき：締め切りの2日前までに、Issueに書いて助けを求める。
```

## 役割を分ける

役割は、仕事の固定ではなく、「この部分は最初にこの人が気にかける」という目印です。人数が少ないチームでは、一人が複数を兼ねてかまいません。

| 役割 | 受け持つこと |
| :---- | :---- |
| まとめ役 | 集まりの進行、期限の確認、「今だれが何をしているか」の把握。決める人ではなく、決めるための場を整える人。 |
| 記録係 | 話し合いで決めたことと、次にやることをIssueやログに書く。 |
| 調べもの | 資料や事例を集め、出典と一緒に共有する（[AIを使った調べもの](ai-research.md)）。 |
| 作る人 | 文章、図、プログラム、スライドなど、成果物を作る。 |
| 確かめ役 | 作ったものを二人目の目で確かめる。AIの出力の事実確認も含む（[AIの答えを確かめる](checking-ai-output.md)）。 |
| 公開・発表 | 公開の手順を受け持つ。発表の準備を進める（[成果を発表する](presenting.md)）。 |

役割を固定すると、得意な人に負担が集まりがちです。数週間ごとに交代すると、全員が全体を理解できます。

## 決めたことを残す

口頭の約束は、数日で食い違います。話し合いのあとに、次の三つだけを書いて残しましょう。

- 決めたこと：結論と、そう決めた理由を一行。
- 次にやること：だれが、何を、いつまでに。
- 保留にしたこと：まだ決まらず、次回に回すこと。

書く場所は、GitHubのIssueが向いています。やることごとにIssueを作り、担当者を決めておくと、「今だれが何をしているか」が一覧で分かります（[Issuesを「やることリスト」にする](github-collaboration.md)）。LINEなどで決めた場合も、要点をIssueに写します。

<div class="box tip" markdown="1">
<p class="box-title">ポイント</p>

話し合いの記録をAIに手伝ってもらうこともできます。メモを渡して「決めたこと、次にやること、保留にしたことに分けて」と頼むと、整理の下書きができます。ただし、できあがった記録は、その場にいた人が確かめてください。AIは、話されなかったことを補ってしまうことがあります。

</div>

## 意見が合わないとき

意見が割れるのは、チームが考えている証拠です。避けずに、次の順で進めると落ち着いて決められます。

1. 違いを言葉にする。「Aさんは範囲を広げたい、Bさんは絞りたい」のように、何が違うのかを書き出す。
2. 理由を聞く。結論の前に、なぜそう考えるのかを順に聞く。
3. ゴールに戻る。最初に決めたゴールと期間から見て、どちらが近いかを考える。
4. 小さく試す。決めきれないときは、短い時間で両方を試し、結果を見て決める。
5. 決め方を決めておく。それでも割れたら、まとめ役が決める、多数決にする、など。

意見は人ではなく案に向けます。「その案だと、期間内に終わらないかもしれません」と言い、「あなたの案はだめ」とは言いません。

## チームでAIを使う約束

チームでAIを使うと、AIが出したものを、だれがどこまで確かめたのかが見えにくくなります。次の点を約束しておきましょう。

- AIに頼んだ部分は、記録に書く（どのAIに何を頼んだか）。
- AIが作った文章、図、プログラムは、作った本人以外の一人が確かめてから取り込む。
- 個人情報や、公開してはいけない資料をAIに貼らない（[AIを使うときの倫理とルール](ai-ethics.md)）。
- 全員が同じ水準で理解できていることを、時々確かめる。AIに任せて、チームの中でだれも分からない部分ができないようにする。

## 困りごとが起きたら

- 連絡が取れないメンバーがいる：まず、責める形でなく、「困っていないか」と声をかける。連絡の場所と返事の目安を、約束の中に決めておくと、気づくのが早くなる。
- 作業が偏っている：Issueの担当者の一覧を見て、数と重さを並べて話し合う。
- 話し合いがまとまらない：まとめ役が論点を一つに絞る。
- どうしても解決しない：早めに教員やTAに相談する。相談先と方法は授業での案内に従う。
