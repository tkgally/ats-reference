## プロジェクトは5つの段階で進む

この授業は、自分の関心にもとづくプロジェクトに取り組みながら学ぶ実践型（PBL、プロジェクト型学習）の授業です。シラバスでは、プロジェクトを「テーマ設定、計画、実装、評価、発表」の順に進めることになっています（[PBL（プロジェクト型学習）](../../../wiki/concepts/project-based-learning.md)）。

ただし、実際のプロジェクトは一直線には進みません。作ってみて評価したら思ったとおりでなかった、ということはよくあります。そのときは実装や計画に戻ってやり直します。何度か行き来しながら少しずつ良くしていくのが、ふつうの進み方です。

{{svg:project-workflow-cycle.svg}}
<figcaption>プロジェクトの5つの段階。どの段階でもAIは手伝えるが、何を選び、何を良しとするかは自分で判断する。</figcaption>
</figure>

AIツールは、どの段階でも頼りになる相棒です。アイデアを出す、調べる、作業を分ける、文章や画像やプログラムを作る、点検する、発表の構成を考える、といった作業を手伝ってくれます。一方で、「自分は何をやりたいのか」「この結果で十分か」「何を伝えたいのか」を決めるのは自分です。この授業のねらいの一つは、AIに任せるところと自分で判断するところを見分けられるようになることです。

## テーマを決める

テーマは、研究、創作、社会課題の解決、ビジネス提案など、自由に選べます（[授業の概要](../../../wiki/course/course-overview.md)）。次の表は、考えるときの手がかりとしての例です。

| 種類 | テーマの例 | できあがるものの例 |
| :---- | :---- | :---- |
| 研究 | 大学周辺の飲食店の価格と立地の関係を調べる | 調査レポート、グラフ、知識ベース |
| 創作 | 世田谷を舞台にした短編小説と挿絵を作る | 作品、制作の記録 |
| 社会課題 | 留学生向けに、ゴミ出しの規則を分かりやすく説明するサイトを作る | ウェブページ、利用者の感想 |
| ビジネス提案 | 学生の空き時間を使った新しいサービスを企画する | 企画書、試作品、発表資料 |

テーマを探すときは、次の問いから始めると考えやすくなります。

- 最近、気になっていること、もっと知りたいことは何か。
- 日常で「面倒だ」「もっと良くなるはずだ」と感じることは何か。
- 自分の専攻、趣味、アルバイトなどで、ほかの人より詳しいことは何か。
- 学期の終わりに、何ができあがっていたらうれしいか。

AIには、アイデアを広げる相手になってもらいましょう。たとえば「私は鉄道と写真が好きです。AIを使って3か月で取り組めるプロジェクトの案を、研究・創作・社会課題・ビジネス提案から一つずつ出してください」のように頼むと、思いつかなかった方向が見つかることがあります。似たことをすでにやっている人や作品がないかを調べるのにも使えます（AIの答えには間違いもあるので、確かめ方は[AIの答えを確かめる](checking-ai-output.md)を見てください）。

ただし、最後にテーマを選ぶのは自分です。AIが出した案の中で一番「やってみたい」と感じるものを選ぶのが、長い学期を走りきるいちばんの力になります。

## 範囲を決める：野心的だが終わらせられる大きさに

この授業は「野心的なプロジェクト」を勧めています。AIツールを使えば、プログラミングの経験がなくても、以前なら専門家でなければできなかったことに挑戦できます。一方で、学期は限られています。大きな夢を持ちつつ、必ず形になる部分を先に決めておくのがコツです。

<div class="compare" markdown="1">
<div class="good" markdown="1">

範囲がはっきりした例

- 大学周辺の飲食店30軒の価格を集め、地図とグラフで比べる。余裕があれば50軒に増やす。
- 留学生向けのゴミ出し案内を、まず日本語と英語の2言語で作る。

</div>
<div class="bad" markdown="1">

範囲が大きすぎる例

- 日本中の飲食店の価格をすべて調べる。
- あらゆる国の人のための生活アプリを作る。

</div>
</div>

範囲を決めるときは、やりたいことを次の三つに分けてみましょう。

- 必ずやること：これができればプロジェクトとして成り立つ、最小の完成形。
- できればやること：時間に余裕があれば加える機能や内容。
- 夢として書いておくこと：今学期は無理でも、将来やりたいこと。

最初は「必ずやること」だけを目標にして、早めに一通り完成させます。そのあとで「できればやること」を足していけば、時間切れで何も残らないという事態を避けられます。

<div class="box tip" markdown="1">
<p class="box-title">ポイント</p>

範囲を決めたら、AIに「この計画は3か月で終わりますか。無理がありそうなところを指摘してください」と聞いてみましょう。AIの見積もりは正確ではありませんが、見落としている作業に気づくきっかけになります。

</div>

## 計画を立てる

授業は全14回で、2026年9月30日から2027年1月20日まで、水曜日3限に行われます。日程は[授業の日程と進行](../../../wiki/course/schedule.md)にあります。2026年10月7日時点で、第4回以降の各回の内容や、テーマ設定や発表などの段階がどの回に当たるかは、まだ決まっていません。締め切りや発表日は、授業での案内と授業サイトの[ログのページ](https://sites.google.com/view/2026ats/ログ)で必ず確かめてください。

それを前提に、自分の計画の目安を立てておくと安心です。次の図は、計画の立て方を示すための一例です。授業の実際の予定ではありません。

<figure class="fig">
{{svg:project-workflow-timeline.svg}}
<figcaption>全14回を使ったスケジュールの一例（目安）。段階は重なってよく、記録は全期間を通して続ける。</figcaption>
</figure>

計画は次の手順で立てると、AIの力を借りやすくなります。

<ol class="steps">
<li>「必ずやること」を一文で書く（例：「大学周辺の飲食店30軒の価格を地図とグラフで比べる」）。</li>
<li>AIに頼んで、それを小さな作業に分けてもらう（例：「店を選ぶ」「価格を集める」「表にまとめる」「グラフを作る」）。</li>
<li>各作業に、どの回までに終えるかの目安を付ける。年末年始の休みや、ほかの授業の試験の時期も考える。</li>
<li>計画をリポジトリに<code>plan.md</code>のようなファイルとして置き、変わったら書き直す。</li>
</ol>

計画は一度立てたら終わりではありません。進めるうちに分かることが必ずあるので、数回ごとに見直します。計画を変えるのは失敗ではなく、プロジェクトを管理しているということです。

## 実装する

実装は、実際に作る、調べる、書く段階です。学期のうちで一番長い時間を使います。AIエージェント（[AIエージェントとは](ai-agents.md)）やGitHub Copilot（[Copilotのエージェントに作業を頼む](copilot-agent.md)）に作業を頼む場面も多くなります。

実装を進めるときのコツは次のとおりです。

- 小さく作って、すぐ確かめる：一度に大きな作業を頼まず、一つ作るたびに動くか、正しいかを確かめる。
- こまめにコミットする：うまくいった時点でコミットしておけば、次の変更で壊れても戻れる（[GitHubとは](github-basics.md)）。
- AIの出力をうのみにしない：事実、数字、出典、プログラムの動きは自分で確かめる（[AIの答えを確かめる](checking-ai-output.md)）。
- 行き詰まったら頼み方を変える：同じ頼み方を繰り返すより、状況を詳しく説明し直すほうがうまくいく（[AIへの頼み方（プロンプトのコツ）](prompting.md)）。

AIは作業の大部分を手伝えますが、「この結果でよいか」「次に何をするか」を決めるのは自分です。AIが自信ありげに答えても、それが正しいとは限りません。

## 評価する

評価は、できたものが目的を果たしているかを確かめる段階です。評価の基準は、できれば計画の段階で決めておきます。「30軒の価格がそろっている」「留学生3人に読んでもらい、分かりやすいと言ってもらえる」のように、確かめられる形で書いておくと判断しやすくなります。

- 自分で確かめる：基準に照らして、できたこと、できなかったことを書き出す。
- 人に見てもらう：友人、チームの仲間、想定している利用者に使ってもらい、感想をもらう。
- AIに点検してもらう：「この企画書の弱いところを三つ挙げてください」のように頼むと、見落としに気づける。ただし、AIの指摘に従うかどうかは自分で決める。

評価で問題が見つかったら、実装や計画に戻ります。その行き来自体がプロジェクトの成果の一部です。

## 発表する

発表では、何を作ったかだけでなく、なぜそのテーマを選んだか、どう進めたか、AIをどう使い、どこで自分が判断したか、何がうまくいき何がうまくいかなかったかを伝えます。発表の形式や時期は、授業での案内に従ってください。

AIには、発表の構成案を考えてもらったり、スライドの下書きを作ってもらったり、聞き手の役になって質問してもらったりできます。ただし、伝えたいことの中心は自分の言葉で話しましょう。記録を残しておけば、発表の材料はすでにそろっています。

## 個人で取り組むか、チームで取り組むか

プロジェクトには、個人でもチームでも取り組めます（[授業の概要](../../../wiki/course/course-overview.md)）。チームの作り方や人数などは、2026年10月7日時点ではまだ資料がありません。授業での案内に従ってください。

| 形態 | よいところ | 気をつけること |
| :---- | :---- | :---- |
| 個人 | 自分のペースで進められる。テーマを自由に決められる。 | 行き詰まったときに相談相手が少ない。計画が遅れても気づきにくい。 |
| チーム | 役割を分けられる。意見を交わして良くできる。大きなテーマに挑める。 | 話し合いの時間が必要。だれが何をするかを決めておかないと、作業が重なったり抜けたりする。 |

チームで取り組む場合は、一つのGitHubリポジトリを共有し、作業の分担と決めたことをファイルに書いておくと、すれ違いが減ります。ブランチとプルリクエストを使うと、互いの変更を確かめながら進められます（[ブランチとプルリクエストでの共同作業](github-collaboration.md)）。チームで建設的な意見を交わすことは、達成目標の「協働力」にも当たります。

## 記録を残す

プロジェクトのあいだ、何をしたか、何を決めたか、AIにどう頼んでどうなったかを記録しておきましょう。記録は、計画の見直し、評価、発表のすべてで役に立ちます。リポジトリに`log.md`のようなファイルを作り、作業のたびに数行ずつ書き足すのが手軽です。

```
## 2026-10-21
- テーマを「大学周辺の飲食店の価格調査」に決めた。
- AIに作業を分けてもらい、plan.mdを作った。
- 次回まで：調べる店のリストを20軒分作る。
```

記録を書くのが面倒なら、AIエージェントに「今日の作業をlog.mdに追記して」と頼んでもかまいません。さらに進んで、集めた資料や調べたことをエージェントにWikiとして整理してもらう方法もあります。この授業の知識ベースもその方法で作られています（[自分のプロジェクトに知識ベースを作る](knowledge-base.md)）。

## 達成目標とのつながり

シラバスには5つの達成目標があります（[達成目標](../../../wiki/course/learning-goals.md)）。プロジェクトの進め方と、次のように結びついています。

| 達成目標 | プロジェクトのどこで身につくか |
| :---- | :---- |
| AI活用能力 | 段階ごとに目的に合ったツールを選び、使い分ける。 |
| プロジェクト遂行力 | テーマ設定から評価まで、計画を立てて自分で進める。 |
| 問題解決力 | 大きな課題をAIと一緒に小さな作業に分け、解決策を作る。 |
| 協働力 | チームの仲間や利用者から意見をもらい、成果を良くする。 |
| 倫理的判断力 | 著作権やプライバシーに気を配りながらAIを使う（[AIを使うときの倫理とルール](ai-ethics.md)）。 |

評価の方法や基準は、2026年10月7日時点ではまだ資料がありません。分かりしだいWikiに反映されます。
