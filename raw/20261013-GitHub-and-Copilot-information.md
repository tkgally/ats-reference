# GitHub Copilotデスクトップアプリを使い始めるために必要なこと（教員とIT担当者向けガイド）

東京都市大学「AIとの探検ゼミナール」で、受講生が大学から配られたGitHubアカウントを使い、GitHub Copilotデスクトップアプリで自分のリポジトリを扱い始めるために必要なことをまとめた文書です。作成日は2026年10月13日です。

アプリの入手先と概要は、公式ドキュメントの[GitHub Copilot アプリ](https://docs.github.com/ja/copilot/concepts/copilot-surfaces/github-copilot-app)です（2026年10月13日に確認）。この文書には、公式の資料でまだ確認できていない点も含まれます。そうした点は「要確認」と書き、最後の節に、IT担当者に確かめたい質問を一覧にしました。

## 1. 全体の流れ

受講生がすることは、大きく次の7段階です。

1. 準備：パソコン、ネット接続、スマートフォン（二要素認証用）を用意する。
2. GitHubにログインする：大学から配られたアカウントで、初めてログインする。
3. 二要素認証を設定する：ログインの保護を設定する。
4. Copilotが使えることを確かめる：アカウントにCopilotの利用権が付いているかを見る。
5. Copilotデスクトップアプリを入れてサインインする：インストールして、GitHubのアカウントでサインインする。
6. リポジトリを作る：GitHubで練習用のリポジトリを作る。
7. アプリでリポジトリを開き、Copilotに作業を頼む：変更を確かめ、GitHubに反映する。

つまずきやすいのは、2、3、4の三つです。大学が配ったアカウントは、自分で作るふつうのアカウントとは仕組みが違う可能性があるためです。

## 2. 最初に確かめるべきこと：アカウントの種類

大学が配ったGitHubアカウントには、おもに二つの種類が考えられます。どちらかによって、ログインの方法や、できることが変わります。IT担当者に、どちらなのかを必ず聞いてください。

### A. 管理されたユーザーアカウント（Enterprise Managed Users、EMU）

大学（組織）がアカウントを作り、管理する方式です。

- ユーザー名は、大学が決めた形式になるのがふつうです（例：名前の後ろに大学を表す短い文字が付く）。要確認。
- ログインは、大学のシングルサインオン（SSO）を通ります。TCUアカウントのユーザー名とパスワードでログインすることになると思われます。要確認。
- 二要素認証は、GitHub側ではなく、大学のログインの仕組み（TCUアカウントの多要素認証）で行われると思われます。要確認。
- 管理されたアカウントには、できないことがあります。たとえば、公開（Public）のリポジトリを作れない、大学の外の人をリポジトリに招待できない、大学の管理外のリポジトリにコメントや変更を送れない、などです。授業でこの制限が問題になるかを確かめる必要があります。要確認。
- 個人で作るGitHubアカウントとは別のアカウントになります。両方を持つ受講生が混乱しないように、「授業ではどちらを使うか」を明確に伝える必要があります。

### B. ふつうの個人アカウントを、大学の組織に参加させる方式

受講生が自分でアカウントを作り、大学のGitHub組織に招待して参加させる方式です。

- 招待のメールを承諾すると、組織のメンバーになります。
- 組織がSSOを必須にしている場合は、組織のリポジトリを開くときにSSOでの認証を求められます。
- 受講生個人のアカウントなので、卒業後も使い続けられます。

「すでに大学から配られた」という状況から、Aの可能性が高いと思われますが、推測です。要確認。

## 3. 受講生が用意するもの

### パソコン

公式ドキュメントによれば、Copilotデスクトップアプリは、macOS、Linux、Windowsで使えます。授業では、受講生が自分のパソコンを持ち込む前提と思われます。要確認。OSの細かいバージョンなどの条件は、公式の案内で確かめてください。要確認。

インターネットに接続できることも必要です。学内Wi-Fiで、GitHubとCopilotの通信が通るかを、授業の前に一度確かめておくのが安全です。要確認。

### スマートフォン

二要素認証（多要素認証）の認証アプリを入れるために使います。大学の仕組みではMicrosoftのAuthenticatorアプリが使われることが多いですが、TCUがどの方式を指定しているかは分かっていません。要確認。スマートフォンを持っていない人がいる場合の代替手段も、IT担当者に確認してください。要確認。

### 手元に用意してもらうもの

- TCUアカウントのユーザー名とパスワード。
- IT担当者から配られた、GitHubアカウントの情報（ユーザー名、初期パスワード、ログイン用のURLなど）。紙かメールかは要確認。
- 大学のメールを読める状態（確認のメールが届く可能性があるため）。

## 4. 手順の詳細

以下の手順は、一般的なGitHubとCopilotの流れにもとづく見取り図です。大学の設定によって、画面や順番が変わることがあります。IT担当者の説明と食い違ったら、IT担当者の説明を優先してください。

### 手順1：GitHubに初めてログインする

1. ブラウザで、IT担当者が案内したURLを開く。Aの方式なら、大学専用のログインページ（または`github.com`のSSOログイン）になると思われます。要確認。
2. 配られたユーザー名と、TCUアカウントのパスワード（または初期パスワード）でログインする。
3. 初回は、パスワードの変更や、利用規約への同意が求められることがある。
4. ログインできたら、画面右上のアイコンを押し、自分のユーザー名が配られたものと一致していることを確かめる。

GitHubの画面は英語です（2026年10月時点）。授業では[英語の画面を読むための単語帳](site/content/guide/github-english-ui.md)が使えます。

### 手順2：二要素認証を設定する

1. 求められたら、画面の案内に従って二要素認証を設定する。
2. 認証アプリで、QRコードを読み取る。
3. アプリに表示された6桁の数字を入力する。
4. リカバリーコード（または復旧の方法）を、スマートフォンとは別の場所に保存する。

スマートフォンを紛失すると、アカウントに入れなくなる可能性があります。復旧の方法は、IT担当者に説明してもらうべき点です。Aの方式では、二要素認証が大学のログイン側で行われるため、GitHubの設定画面には何も出ないこともあります。要確認。

### 手順3：Copilotが使える状態かを確かめる

1. ログインした状態で、`https://github.com/settings/copilot`を開く。
2. Copilotのプランや利用状況が表示され、有効になっているかを確認する。
3. 「アクセスがない」といった表示のときは、大学の管理者がまだ利用権を割り当てていない可能性がある。その場合は、IT担当者に連絡する。

授業が成立するかどうかを左右する重要な確認です。教室で、全員が一斉に確かめるのがよいと思います。

### 手順4：Copilotデスクトップアプリを入れる

アプリの公式の案内とダウンロードの入口は、次のページです。

https://docs.github.com/ja/copilot/concepts/copilot-surfaces/github-copilot-app

1. 上のページを開き、案内に従って、自分のOS（macOS、Windows、Linux）用のアプリを入手する。
2. ダウンロードしたファイルを開いてインストールする。macOSでは「アプリケーション」フォルダーに移す。Windowsでは画面の案内に従う。
3. 受講生の個人のパソコンの場合、管理者権限（パソコンの設定を変える権限）があるかを確認する。
4. アプリを起動する。

学内のネットワークでは、ダウンロードや認証の通信が制限されている可能性があります。要確認。アプリの動作にGit（変更履歴を記録するソフトウェア）が必要になる可能性もあります。要確認。必要なら、インストールの手順も案内してください。

大学の管理者向けの注意として、公式ドキュメントには次のようにあります。Copilot BusinessとCopilot Enterpriseでは、「GitHub Copilot app」のポリシーが有効になっている必要があります。このポリシーは既定で有効です。大学の組織で無効にされていないかを、IT担当者に確かめてください。

### 手順5：アプリでGitHubにサインインする

1. アプリを起動すると、GitHubでサインインするよう求められると思われる。
2. ブラウザが開くので、手順1と同じアカウント（大学から配られたもの）でログインする。
3. アプリとの連携を許可（Authorize）する。
4. アプリに戻り、自分のユーザー名が表示されていることを確かめる。

ここでの失敗の典型例は二つあります。一つ目は、個人で作ったGitHubアカウントがすでにブラウザにログインしている場合です。その状態で連携を許可すると、授業用ではないアカウントがアプリにつながってしまいます。事前に、ブラウザでは授業用のアカウントだけがログインしている状態にするか、プライベートウィンドウを使うのがよいでしょう。二つ目は、Copilotの利用権がないアカウントでサインインして、Copilotの機能が使えない（または無料の範囲に制限される）場合です。

### 手順6：リポジトリを作る

1. ブラウザでGitHubを開き、右上の+から<span>New repository</span>を選ぶ。
2. Ownerが自分のユーザー名になっていることを確かめる。
3. Repository nameに、半角の英小文字・数字・ハイフンで名前を付ける（例：`ats-practice`）。
4. 公開範囲は、まずPrivate（非公開）にする。Aの方式では、Publicを選べない可能性がある。要確認。
5. Add READMEにチェックを入れ、Create repositoryを押す。

授業のプロジェクト用のリポジトリを、どの公開範囲で、だれの名前で（個人か、組織の中か）作るかは、まだ決まっていません。2026年10月7日の連絡では、大学が調整中とのことでした。要確認。

### 手順7：アプリでリポジトリを開き、Copilotに頼む

1. アプリで、先ほど作ったリポジトリを選ぶ（または自分のパソコンに複製する）。
2. 保存先を聞かれたら、OneDriveなど自動で同期されるフォルダーの中は避ける。
3. セッションのモードを選ぶ。公式ドキュメントによれば、対話型（一緒に進める）、プラン（計画を立てて承認する）、Autopilot（完全に自律的）の三つがある。最初は対話型かプランにする。
4. チャットの入力欄に、日本語で頼みたいことを書く（例：「READMEに、この授業で何をしたいかを一文追加してください」）。
5. Copilotが提案した変更を確かめ、フィードバックを返すか、そのまま残す。
6. 変更をGitHubに反映し、ブラウザでGitHubを開いて反映されたことを確かめる。

公式ドキュメントによれば、アプリはセッションごとに専用のブランチ（作業の枝）を作って作業します。変更をどう反映するか（プルリクエストの作り方など）は、操作しながら確かめるのがよいと思います。教員がまず自分で一度通して試し、画面の写真を残しておくと、授業で説明しやすくなります。

公式の入門ページ（[GitHub Copilot アプリを使い始める](https://docs.github.com/ja/copilot/get-started/quickstart-copilot-app)）も、あわせて読んでおくと役に立つと思われます（中身は未確認）。

## 5. 授業中の安全のための約束

受講生に、最初に伝えておくとよいことです。

- 学籍番号、成績、他人の個人情報、パスワード、APIキーなどを、リポジトリやCopilotへの入力に書かない。
- 非公開のリポジトリでも、共同作業者として招待した人には見える。招待は、チームの仲間と教員だけにする。
- Copilotが操作の許可を求めたとき（ファイルの書き換えやコマンドの実行）は、内容を読んでから許可する。分からなければ許可せず、質問する。
- Autopilot（完全に自律的）は、慣れるまで使わない。
- パスワードや認証アプリのコードを、他人に教えない。IT担当者や教員も、パスワードを聞くことはない。

## 6. 明日のIT担当者の説明で確かめておきたい質問

### アカウントについて

1. 配られたアカウントは、管理されたユーザーアカウント（EMU）か、組織に参加させる個人アカウントか。
2. ユーザー名の形式は何か。初期パスワードはあるか。
3. ログインのURLはどこか。SSOを使うなら、TCUアカウントでログインするのか。
4. 二要素認証は、どこで、どの方式（アプリ、SMSなど）で設定するのか。スマートフォンがない人はどうするか。
5. パスワードや認証アプリを忘れた・なくしたときの連絡先と手順は何か。
6. 学期が終わった後、アカウントはいつまで使えるか。リポジトリのデータはどうなるか。
7. すでに個人のGitHubアカウントを持っている受講生は、どう使い分けるべきか。

### Copilotについて

8. Copilotの利用権は、全員に割り当て済みか。どのプランか（Business、Enterpriseなど）。
9. 組織の設定で、「GitHub Copilot app」のポリシーは有効になっているか。
10. 使えるAIモデルに制限はあるか。利用量の上限はあるか。
11. 入力した内容がAIの学習に使われないという保証はあるか（データの扱いの設定）。
12. 受講生が、モデルの選択や機能のオン・オフを自分で変えられるか。

### リポジトリについて

13. 受講生は、自分のアカウントの下にリポジトリを作れるか。それとも、組織の下に作るのか。
14. 公開範囲は、何を選べるか（Private、Internal、Public）。
15. 大学の組織に入っていない外部の人を、リポジトリに招待できるか。
16. 教員が受講生のリポジトリを読むための権限は、どう設定するか。
17. 教員が受講生全員のリポジトリを一覧できる仕組み（組織やチームの設定）は作れるか。

### アプリと環境について

18. 受講生に、公式ページ（https://docs.github.com/ja/copilot/concepts/copilot-surfaces/github-copilot-app ）からダウンロードしてもらってよいか。大学として別の配布方法（指定の場所など）はあるか。
19. 学内のネットワークで、GitHub、アプリ、認証の通信は通るか。通らない場合の別の手段（スマートフォンのテザリングなど）はあるか。
20. 受講生のパソコンに、Gitなどの追加のソフトが必要か。管理者権限がないパソコンでもインストールできるか。
21. 大学の貸出用のパソコンを使う受講生はいるか。いるなら、同じ設定でよいか。

## 7. 明日の教室での進め方（案）

IT担当者の説明を、次の順番で進めてもらうと、つまずきを減らせます。

1. 受講生は、パソコン、スマートフォン、配られたアカウントの情報を机の上に出す。
2. 手順1と手順2（ログインと二要素認証）を、全員で同時に進める。ここで止まっている人を早めに見つける。
3. 手順3（Copilotが使えるかの確認）を全員でする。使えない人の一覧を、IT担当者に渡す。
4. 手順4と手順5（アプリのインストールとサインイン）を進める。
5. 時間があれば、手順6と手順7（リポジトリの作成と、最初のCopilotへの頼み）まで進める。終わらなかった人は、次回までの宿題にする。
6. 最後に、できた人・できなかった人を確認し、IT担当者の連絡先（問い合わせ窓口）を受講生に伝える。

段階ごとに「ここまでできた人は手を挙げて」と確かめながら進めるのがおすすめです。

## 8. よくあるつまずきと対処

### ログインできない

ユーザー名の形式、パスワード（TCUアカウントのものか、初期パスワードか）、大文字と小文字、SSOのログインURLを確かめます。

### 二要素認証のコードが合わない

スマートフォンの時刻が自動設定になっているかを確かめます。コードは30秒ごとに変わるので、表示されたらすぐ入力します。

### ログインしたが、Copilotが使えない

`https://github.com/settings/copilot`の表示を確かめます。利用権が未割り当てなら、IT担当者に連絡します。

### アプリが使えない、または使用が許可されていないと表示される

組織の「GitHub Copilot app」のポリシーが無効になっている可能性があります。IT担当者に連絡します。

### アプリで、別のアカウントでサインインしてしまった

アプリでサインアウトし、ブラウザでも別のアカウントからサインアウトしてから、やり直します。

### リポジトリが作れない

作る場所（個人か組織か）と、公開範囲の制限を確かめます。組織の設定で制限されている可能性があります。

### アプリのインストールができない

管理者権限、OSの対応、セキュリティソフトのブロックを確かめます。

### 通信エラーが出る

学内Wi-Fiの制限が考えられます。スマートフォンのテザリングで試します。

### 画面が英語で分からない

[英語の画面を読むための単語帳](site/content/guide/github-english-ui.md)を引くか、画面の写真をAIに見せて、日本語で聞きます。

## 9. 今のところ分かっていないこと

このリポジトリのWikiと解説サイト、および公式ドキュメントで確認できたことと、できていないことを分けておきます。

確認できていることは次のとおりです。

- 大学の予算で、GitHub Copilotの有料版が全員に提供される予定であること（2026年10月7日時点で、大学がMicrosoftと調整中）。
- 授業のリポジトリの公開範囲は、まだ決まっていないこと。
- Copilotデスクトップアプリは、すべてのCopilotプランで使え、macOS、Linux、Windowsに対応していること（公式ドキュメント、2026年10月13日に確認）。
- BusinessとEnterpriseでは、組織の「GitHub Copilot app」ポリシーが有効である必要があり、既定では有効であること（同上）。

確認できていないことは次のとおりです。

- アプリのインストールと初回サインインの、画面ごとの具体的な手順。
- 大学が配ったGitHubアカウントの種類、ユーザー名の形式、ログインの方法。
- TCUアカウントの多要素認証の設定手順。
- 大学の組織で、「GitHub Copilot app」のポリシーが有効になっているか。

明日の説明が終わったら、IT担当者が話した内容を、このリポジトリの解説サイトに反映するとよいと思います。その際は、画面の写真と、決まった手順をお知らせください。
